# GEO 内部工作台前端演示

## 运行

```bash
cd frontend
npm install
npm run dev
```

然后在本机浏览器打开终端显示的 `Local` 地址。若默认 5173 端口被占用，Vite 会自动切换端口，请以终端实际地址为准。

构建检查：`npm run build`。

## 已实现

- 标准题库：6 道**演示草稿**，可新增、编辑；编辑后问题版本递增。
- 首轮基线：按当前题库和 4 个引擎生成组合，记录固定的问题文本与版本。
- 人工采样：区分有效命中、有效未命中、执行失败、待人工复核；保存原始回答、原始引用 URL、采样模式和失败原因。
- 概览：计划数、完成数、有效回答数和品牌提及率。失败与待复核不进入有效回答分母。
- 本地持久化：浏览器 `localStorage`，可从概览重置。

所有内容均为本地演示数据。品牌题中的 `【基地全称】` 是占位符；正式使用前需要确认品牌全称和标准题目。没有接入登录、权限、后端任务、截图上传、审核或真实统计接口。

## 与后端共同确认的数据边界

目前**没有约定任何 API 路径或响应格式**。`src/model.ts` 定义的是前端暂用视图模型，`src/storage.ts` 是本地数据源。联调时请共同确认以下事项，再以服务端数据源替换 `storage.ts`：

1. 项目授权与项目标识：请求的项目上下文由后端校验，前端选择项目不构成权限边界。
2. 问题版本：更新问题是否由服务端创建不可变版本；监测记录须引用固定版本和问题快照。
3. 基线唯一键：轮次 + 问题版本 + 引擎 + 采样序号；创建接口需支持幂等。
4. 采样状态和失败原因枚举、状态转换、采样时间来源，以及人工复核人和复核时间。
5. 原始回答、引用 URL、截图/附件和 URL 归一化字段及上传方式；原始证据不可被复核结果覆盖。
6. 列表分页、筛选、错误格式；指标计算由服务端按确认的规则版本提供。

演示页中的引用 URL 只用于查看录入情况，**不代表已复核引用率**。正式引用率须按技术方案中“基地相关且已复核来源链接”的口径由服务端计算。
