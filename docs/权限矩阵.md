# 工作台权限矩阵

> 日期：2026-11-18  
> 事实源：后端路由能力门禁 + 前端导航元数据  
> 相关方案：`docs/工作台页面可见性与权限分级方案.md`

## 1. 角色定义

| 角色码 | 定位 | 关键能力 |
|---|---|---|
| `sys_admin` | 系统管理员 | `project.create`、`engine.manage`；不默认拥有项目业务数据权限 |
| `project_admin` | 项目管理员 | 管本项目成员；全部项目读能力；审核、渠道/竞品/品牌/指标写；`engine.verify`、`export.data`、`audit.read`、预算查看/提交/审批；可确认项目资料与优先级；可修改项目业务时区 |
| `editor` | 运营/编辑 | 题库、监测执行、内容写、发布执行、渠道/竞品/品牌写；`engine.verify`、`export.data`、预算查看/提交；**不持有 `metric.manage`**（项目口径与指标口径写入已收窄为项目管理员） |
| `reviewer` | 审核 | 内容审核、证据复核、统计/审计只读、预算查看/审批；不改正文、不发布 |
| `viewer` | 只读 | 全部项目读能力 + `export.data`；所有写操作拒绝，无预算权限 |
| `lead_ops` | 招生/客服 | 只能读写本项目线索，无预算权限 |

- `leadAccess=forbidden` 时不展示线索菜单，不再用“无权限”占位。

## 4. 后端代表接口

| 接口 | 门禁 | 允许角色 | 备注 |
|---|---|---|---|
| `GET /api/v1/engines` | 系统管理员或任一项目 `engine.verify` | `sys_admin`、`project_admin`、`editor` | `viewer`/`reviewer`/`lead_ops` 403 |
| `GET /api/v1/engines/{id}/entries` | 同上 | 同上 | 非系统管理员裁剪 API 入口 `entry_url` / `credential_ref` |
| `POST /api/v1/engines/{id}/entries` | `engine.manage` | `sys_admin` | 创建/更新/测试均同 |
| `GET /api/v1/projects/{id}/monitoring/diagnostics` | `monitoring.execute` 或 `project.member.manage` | `editor`、`project_admin` | `viewer`/`reviewer`/`lead_ops` 403 |
| `GET /api/v1/projects/{id}/monitoring/traces/{trace_id}` | 同上 | `editor`、`project_admin` | 同上 |
| `GET /api/v1/projects/{id}/leads` | `lead.read` | `project_admin`、`viewer`、`lead_ops` | `editor`/`reviewer` 403 |
| `GET /api/v1/projects/{id}/members` | `project.member.manage` | `project_admin` | 其他角色 403 |
| `GET /api/v1/projects/{id}/audit-logs` | `audit.read` | `project_admin`、`reviewer` | 其他角色 403 |
| `POST /api/v1/projects/{id}/confirm` | `project.confirm` | `project_admin` | 系统管理员无成员身份时不能越过项目边界 |
| `PUT /api/v1/projects/{id}/timezone` | `project.timezone.manage` | `project_admin` | 先 `SELECT ... FOR UPDATE` 锁项目行、再读旧值，两个管理员并发修改时审计链连续；`editor`/`reviewer`/`viewer`/`lead_ops` 与无成员身份的 `sys_admin` 一律 403 |

| `PATCH /api/v1/projects/{id}/metric-definitions/{metric_id}` | `metric.manage` | `project_admin` | 同上 |
| `PUT /api/v1/projects/{id}/stats/policies` | `metric.manage` | `project_admin` | 项目口径写入；`editor` 403 |
| `PUT /api/v1/projects/{id}/stats/adaptation` | `metric.manage` | `project_admin` | 同上 |

- `lead_ops`（`lead.write`）与 `project_admin`：列表和 CSV 导出均返回完整手机号/微信。
- `viewer`：列表和 CSV 导出均脱敏，例如手机号 `138****0002`、微信 `wx****an`。

## 8. 部署前置：新权限的幂等补齐

`project.timezone.manage` 是新增能力码。代码矩阵允许 `project_admin` 修改时区，但运行库的 `permissions`
与 `role_permissions` 没有对应记录时，实际请求仍返回 403。上线前必须补齐——**但不要整份跑 `seed.py`**：

`seed.py` 是完整种子，除了能力码还会创建管理员账号、引擎目录、项目业务数据与 FAQ，
副作用不在本次变更范围内。补权限请只用专用脚本：

```bash
cd backend
python scripts/sync_permissions.py --check        # 先看差异，不写库；有差异退出码 1
python scripts/sync_permissions.py                # 补齐（只增不删，幂等，可重复执行）
python scripts/sync_permissions.py --revoke-stale # 补齐 + 撤销代码矩阵已移除的历史授权（逐行打印后再删）
```

需要 `--revoke-stale` 的典型场景：某个能力从角色上收窄（`metric.manage` 已从 `editor` 移除），
旧环境里那条授权还在并继续生效。脚本默认不删，避免误删运行时动态授权的记录。

执行后核对结果，预期只有一行：

```sql
SELECT r.code AS role_code, p.code AS permission_code
FROM role_permissions rp
JOIN roles r ON r.id = rp.role_id
JOIN permissions p ON p.id = rp.permission_id
WHERE p.code = 'project.timezone.manage'
ORDER BY r.code;
```

预期输出 `project_admin | project.timezone.manage`。若为空，说明库授权未补齐，此时即使代码矩阵正确，
`PUT /api/v1/projects/{id}/timezone` 对所有角色仍是 403。

再用漂移检查确认库与代码一致（CI 也跑这条）：

```bash
python scripts/check_permission_drift.py --doc ../docs/权限矩阵.md
```
