# C2 真实链路验收（DB → API → 前端）

目的：证明真实 PostgreSQL、真实后端窗口计算、真实前端展示三者一致，而不是只证明 mock 展示不变。
对应审查缺口：C2-4「前端展示与服务端返回一致」。

## 一、组成

| 件 | 路径 | 作用 |
| --- | --- | --- |
| 夹具脚本 | `backend/scripts/c2_live_fixture.py` | 建上海/纽约/柏林三个项目，各写 4 条边界事实与专属账号 |
| 验收用例 | `frontend/e2e/c2-live-window.spec.ts` | 逐项目登录真实前端，读 API 事实并比对 DOM，再在三个浏览器时区重复 |
| 开关 | `GEO_C2_LIVE=1`、`C2_LIVE_FIXTURE`、`C2_LIVE_API`、`E2E_BASE_URL` | 默认跳过，避免污染日常回归 |

## 二、夹具数据结构

每个项目在"今天窗口"的四条边界写入 `Fact`（DRAFT，进入待办）：

| 落点 | 相对窗口 | 是否应计入 today |
| --- | --- | --- |
| `start - 1s` | 窗口外 | 否 |
| `start` | 左边界 | 是 |
| `end - 1s` | 右边界前 | 是 |
| `end` | 右边界 | 否 |

预期：`today = 2`、`all = 4`；`week` 由脚本按周窗口单独核算（若当天是周一，`start - 1s` 落在上周）。

## 三、执行步骤

```powershell
# 1) 夹具（backend 目录，.env 指向目标库）
cd backend
.venv\Scripts\python.exe scripts\c2_live_fixture.py --manifest c2_live_manifest.json > c2_live.json

# 2) 后端（8000）与真实前端（3220，不要设 GEO_API_MODE）
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 另开窗口：cd frontend; pnpm exec next dev --port 3220

# 3) 验收
cd frontend
$env:E2E_BASE_URL="http://127.0.0.1:3220"
$env:GEO_C2_LIVE="1"
$env:C2_LIVE_API="http://127.0.0.1:8000"
$env:C2_LIVE_FIXTURE="<上一步 c2_live.json 的绝对路径>"
pnpm exec playwright test e2e/c2-live-window.spec.ts --config=playwright.config.ts

# 4) 清理（只认本次 manifest，按精确 UUID 删）
cd ../backend
.venv\Scripts\python.exe scripts\c2_live_fixture.py --cleanup --manifest c2_live_manifest.json
```

## 三之二、工具安全约束（fail-closed）

夹具会在真实库建/删数据，因此脚本自身带四道闸门：

| 闸门 | 行为 |
| --- | --- |
| 库身份 | `make_url()` 解析库名，默认只允许 `geo_dev_migrated`；其他库直接拒绝（连清理也拒绝） |
| 显式扩展 | 需要别的验收库时设 `C2_LIVE_ALLOW_DATABASES="db1,db2"`，不靠猜 |
| 一次一 ID | 每次创建生成 `fixture_run_id`，项目/账号名前缀都带该 ID，避免与历史夹具混淆 |
| manifest 清理 | 清理只接受本次 manifest，校验库名、run 前缀、UUID 合法性；按精确 ID 删项目/成员/事实/账号，不再按 `c2live-%` 扫描 |
| 可审计 | 删除前打印库名、fixture ID、manifest 项目数、实际命中数、待删事实/成员数；数量不符就拒绝 |

对应单测：`backend/tests/test_c2_live_fixture_guard.py`（8 条，覆盖库白名单、manifest 缺字段、跨库 manifest、跨 run 项目、非法 UUID）。

## 四、断言内容

1. `business_timezone` 等于项目时区，`window.start/end` 等于夹具打印的窗口。
2. `generated_at` 存在；`range=all` 时 `window` 为 `null`。
3. API `counts.today/week/all` 等于夹具按边界算出的期望值。
4. 前端待办中心的"今天/本周/全部"按钮计数等于 API 计数；六类分组汇总与待办行来自同一份数据。
5. 同一项目在 `Asia/Shanghai`、`America/New_York`、`Europe/Berlin` 三个浏览器时区下，计数、汇总、行标题完全一致。

**证据分工（重要）**：夹具用 `project_calendar()` 取窗口边界，与服务端同源，因此它**不是独立的日期算法 oracle**；它证明的是"同一窗口穿过数据库、API、UI 后没有被任何一层改写"。真正独立、硬编码的 UTC 期望由 `tests/test_dst_matrix_e2e.py` 的 19 格承担。两类测试不可互换，也不能把夹具结果当作算法正确性的独立证明。

## 五、已知限制

1. 夹具用"建数据时的当前时刻"切窗；若验收跨过本地零点，用例会显式跳过并提示重跑夹具（不会伪装通过）。
2. 本用例需要真实后端 + 真实前端同时在线，未纳入 `backend-ci.yml`（CI 目前只跑 mock 前端与后端矩阵）。它是部署前/阶段关闭前的手工门禁，命令与判定都固定在本文件。
3. 用例只覆盖事实（facts）这一类待办，其他五类共用同一窗口函数与同一接口，不重复造样本。
