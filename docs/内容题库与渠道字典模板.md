# 内容题库与渠道字典模板（C 侧草案）

> 用途：给运营确认正式问法、给 B 做任务生成、给 C 做导入与巡检。
> 边界：本文件是**候选模板**，不是最终文案。所有题目先以 `draft` 导入，运营确认后再统一激活；C 不改写运营最终问法。

## 一、题库导入字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `code` | 是 | 项目内唯一，建议 `Q01` 起顺序编号；不要复用已归档题编码 |
| `title` | 是 | 用户真实会问的一句话；不写营销口号，不堆关键词 |
| `question_type` | 是 | `brand`：问基地/品牌；`general`：问品类、地域、人群、场景 |
| `audience` | 是 | 人群画像，例如“零基础转行者”“比价阶段家长” |
| `intent` | 是 | 意图，例如“核验资质”“比较价格”“准备作品集” |
| `priority` | 是 | 100 为默认；数字越小越优先（与现有 seed 口径一致） |
| `status` | 是 | 导入一律 `draft`；只有运营确认后才改 `active` |
| `current_version_no` | 是 | 首次导入为 `1`；正文版本号从 1 起 |
| `keyword_codes` | 否 | 逗号分隔，挂到 `content_version_keywords` 前先确认关键词存在 |

导入后必须能回答：**这条题属于哪个人群、什么意图、优先级多少、对应哪条内容版本**。

## 五、内容结构公式（C 只做校验，不写最终文案）

| 区块 | 要求 | 对应字段/检查 |
| --- | --- | --- |
| 标题 | 人群 + 地域 + 问题，和 `questions.title` 一致或高度对应 | `content_items.title` |
| 首段 | 前 80–120 字直接回答，不绕背景 | `content_versions.body` |
| 事实块 | 基地全称、地址、课程、时长、价格区间、就业服务 | 正文 + 来源 |
| 证据块 | 资质、证书、案例、报道、数据，至少 2 条 | 正文 + `content_version_citations` |
| 对比块 | 自学 / 大学课程 / 机构实训的差异 | 正文 |
| FAQ | 5–8 条真实追问，逐条短答 | 正文 |
| CTA | 试听、咨询、地图、表单四选一，不假设 AI 答案会显示电话 | 正文 + `landing_url` |
| 关联 | 必须挂题目与关键词 | `content_version_questions` / `content_version_keywords` |

发布前至少满足：`content_versions.status=approved`、正文哈希已记录、题目/关键词已挂、渠道稿有 `publish_task`；发布后必须有 `publish_receipt.published_url` 才能结案。

## 六、导入顺序

1. 先导渠道与域名别名，保证引用能归类；
2. 再导 30 条候选题目，全部 `draft`；
3. 运营确认正式问法后，只把确认过的题改 `active`；
4. 内容侧按题写版本，审批后挂题目/关键词；
5. 发布任务按 `account + channel + version + task_key` 幂等创建；
6. 回执 URL 落库后，才允许进入“已发布”统计；
7. 跑 `scripts/validate_content_coverage.py --project-code <项目>` 检查闭环。
