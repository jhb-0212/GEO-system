## 三、部署步骤（按序执行，命令与输出原样留存）

```bash
# 1. 取交付版本（固定 commit，不随分支移动）
git clone <仓库地址> geo-system && cd geo-system
git fetch origin
git checkout <RELEASE_COMMIT>
git rev-parse HEAD                              # 期望 <RELEASE_COMMIT>…；2026-11-23 参考：代码基准 22ab176，A-1 出基 72f2fa4
git status --porcelain                          # 期望无输出

# 2. 准备环境文件与证书（不进仓库）
cp deploy/.env.prod.example deploy/.env.prod    # 按第二节逐项改
# 证书放到 deploy/nginx/certs/；当前 self-signed 仅可用于内网演练
# 如沿用本机已填的 .env.prod，至少改 PUBLIC_API_BASE_URL / CORS_ORIGINS / 域名

# 3. 配置校验（必须先过）
docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod config >/dev/null && echo CONFIG_OK

# 4. 构建并启动（migrate 一次性建表 + 种子；api/worker 等它成功）
docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod up -d --build

# 5. 等待与状态
docker compose -f deploy/docker-compose.prod.yml ps        # 8 服务，migrate 退出码 0
docker compose -f deploy/docker-compose.prod.yml logs migrate | tail -30

# 6. AI 目录核对（期望 engines=15；6 条扩展入口均 is_active=f；Kimi/千问/秘塔/360/讯飞/智谱 supports_search=t）
docker compose -f deploy/docker-compose.prod.yml exec -T postgres \
  sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select e.code, en.entry_type, en.protocol, en.is_active, en.supports_search from ai_engine_entries en join ai_engines e on e.id=en.engine_id where e.code in ($$kimi$$,$$qianwen$$,$$metaso$$,$$nami_ai$$,$$zhipu$$,$$spark$$) order by e.code;"'
```

## 四、上线验收（每条都要真实输出，不接受"应该可以"）

> 下列 HTTP 检查在 Linux/macOS 可直接用 `curl`；Windows 用 `Invoke-WebRequest`、浏览器或任意 HTTP 客户端等价执行，判据相同。

```bash
# 入口与证书
curl -sS -o /dev/null -w '%{http_code} %{ssl_verify_result}\n' https://<域名>/health
curl -sS https://<域名>/health/db
curl -sS https://<域名>/health/redis
curl -sS https://<域名>/health/worker
curl -sS https://<域名>/health/queue
# 超时/失败即 503，body 里 error.code 与 reason 可区分 none/stale/unavailable

# 日志与请求号
curl -sSI https://<域名>/health | grep -i x-request-id   # Windows 用等价方式读响应头
docker compose -f deploy/docker-compose.prod.yml logs api --tail 20    # 应为一行行 JSON，request_id 与上面一致

# 调度：beat 独立运行（全局只能一个），确认周期任务在投递
docker compose -f deploy/docker-compose.prod.yml ps beat          # 期望 healthy
docker compose -f deploy/docker-compose.prod.yml logs beat --tail 20 | grep 'Scheduler: Sending'
# 判据：日志中出现 geo.outbox.dispatch / geo.monitoring.schedule 的 Sending 记录

# 任务失败告警（自检任务，投递即失败）
docker compose -f deploy/docker-compose.prod.yml exec worker \
  python -c "from app.worker import celery_app; print(celery_app.send_task('geo.selftest.fail').id)"
# 判据：告警接收端收到 event=task_failed，含同一 task_id

# 备份 + 失败告警（按宿主 OS 选脚本）
./deploy/scripts/backup_db.ps1 -AppEnv prod -AlertWebhook <地址>        # Windows / PowerShell
BACKUP_ALERT_WEBHOOK=<地址> APP_ENV=prod bash ./deploy/scripts/backup_db.sh  # Linux
```
