# 样本口径声明（对外验收附件）

> 用途：随报告/验收单一并交付，回答「这个数字是怎么算出来的、哪些没算」。文案与 `docs/metric-dictionary.md` 一致，任何数字都能在字典里找到分子、分母与排除项。

## 一、样本基座

- 采集对象：指定引擎 × 指定问题版本 × 指定轮次的一次真实查询结果。
- 有效样本：`status ∈ {hit, miss}` 的样本；失败、待复核、无答案面、未完成一律单列计数，不进任何比率。
- 答案口径：生成回答（`answer`）与检索结果（`search_result`）各自独立分母，不合并算提及率。
- 题目分区：通用题（`general`）用于自然发现率；品牌题（`brand`）是功能验证，默认不合算。
- 时间窗：报告默认取「本轮/指定区间」，跨轮不累加；比率旁必须标出实际样本数与时间范围。

## 二、五个分项与新增两项

| 指标 | 分子 | 分母 |
|---|---|---|
| 提及率 | 提及品牌的有效样本 | 有效样本 |
| 首推率 | 品牌位次第 1 的有效样本 | 有效样本 |
| 信源覆盖 | 自有域名命中的已复核引用去重域名数 | 已复核引用去重域名总数 |
| 竞品位次 | 品牌不劣于最优竞品的样本 | 双方都有位次的样本 |
| 引用上下文质量 | 标题/摘要含品牌名的已复核引用 | 已复核引用总数 |
| **被引用率（三分 cited）** | 提及品牌 **且** 有已复核带 URL 引用的样本 | 有效样本 |
| **品类信源覆盖** | 自有域名或已投站点命中的域名数 | Top N 已复核引用域名（默认 20） |

三分互斥：被引用且带链接 / 仅提及无链接 / 未出现品牌，三档相加严格等于有效样本数。

## 三、明确不做的算法

- 不做综合评分、健康度、等级、百分位排名；分项之间不可相加、相乘、比大小。
- 不做「行业均值」「竞品基准」推断；未采集到基线就写「未采集」。
- 不做效果担保（如「90 天 70% 提及」）；只给可复算的数字。
- 分享额（SoV）不做归一化：一个回答同时提到多方时各方都计 1，份额相加可超过 100%，它衡量曝光普遍度，不是投票。

## 四、引用不可观测时怎么算

- 引擎不展示引用来源（`supports_citation=false`）时，引用相关指标返回「不可观测」并给出条数，不算 0，也不进引用率分母。
- 被引用率此时只可能落到「仅提及无链接」，不能因为看不到链接就判成「没被引用」。

## 五、数据可核验方式

1. 每条数字都能在统计页按同一筛选复现（轮次、引擎、问题、答案口径、题目分区）。
2. 每条引用都落原始 URL、域名、复核状态与复核人；未复核引用不进分母。
3. 采样失败按失败码细分单列，可与引擎健康页对照。
4. 发布效果只认「发布回执 URL」命中，不认「我发过某个平台」这种自述。
5. **原始回答存档可回看**：每条样本可存一份不可变快照（`answer_snapshots`），含原始回答、当时的引用清单与题目/引擎上下文，`content_hash` 钉整包、`answer_hash` 只钉回答文本。同一采样重复存档返回既有记录、不覆盖；后续 `raw_answer` 被改写时列表会标 `answer_drift`，原版仍可读。快照不进入任何指标分母，只作复核与离线重跑依据。

## 六、口径变更纪律

改口径先改 `docs/metric-dictionary.md`，再改后端常量与前端文案；同一份报告内不得混用两套口径。历史快照（`stat_snapshots`）冻结时记录范围、分母、规则版本，后续不动态重算。
