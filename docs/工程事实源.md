# 工程事实源

> 本文只说明“去哪里取事实、如何校验”，不保存会随提交变化的具体值。
> 任何当前 commit、表数、OpenAPI 计数、测试通过数量、部署版本，均不得以手工副本进入本文件。

## 一、硬规则

1. 当前值只有唯一事实源，文档只做引用。
2. 生成物只由脚本生成，不手工编辑。
3. CI 只校验生成物与权威事实源是否一致，不维护第二组预期数字。
4. 历史值必须写明日期并标注“历史快照”，不得使用“当前”“以此为准”等表述。
5. 工程测试通过不等于真实业务验收完成。

## 二、事实源映射

| 工程事实 | 唯一权威来源 | 生成 / 校验入口 | 文档引用方式 |
| --- | --- | --- | --- |
| 当前开发主分支 `CURRENT_MAIN` | Git 远端分支 | `git rev-parse origin/main` | 只用于审计、CI 日志、发布评审，不写成固定值 |
| 正式发布版本 `RELEASE_COMMIT` | annotated `v*` release tag | `git rev-list -n1 refs/tags/<release-tag>`；tag object 由 release workflow 复核 | release manifest、部署变量 |
| 镜像身份 `IMAGE_DIGEST` | GitHub Release manifest 的 `repo_digest` | `jq -r '.images.backend.repo_digest' release-manifest.json`；跨主机核对 `docker buildx imagetools inspect` | 部署 `.env.prod` 的 digest-pinned ref、`verify_release.py` |
| 实际部署版本 `DEPLOYED_COMMIT` | 运行中容器 OCI revision label + `RepoDigests` | `deploy/scripts/verify_release.py` | 生产验收记录 |
| Alembic head / current | Alembic 迁移链 | `alembic heads` / `alembic current` / `alembic check` | 命令输出，不手写 head |
| 数据库结构 | 实际 PostgreSQL | `backend/scripts/audit_schema.py` 生成 `docs/表结构核对表.md`；`pg_dump --schema-only` 生成 `docs/数据库DDL.sql`；`backend/scripts/check_schema_ddl.py` 做完整目标库 diff | 引用生成物；CI 对目标库执行完整 DDL 对账 |
| 链路能力矩阵 | 库表、OpenAPI、后端权限门禁、前端页面 | `backend/scripts/audit_capability.py` 生成 `docs/链路能力矩阵.md` | 引用生成物 |
| OpenAPI | `backend.app.main:app` 的 `app.openapi()` | `backend/scripts/export_openapi.py` 生成 `docs/openapi.json`；`--check` 逐字节校验 | 引用 `docs/openapi.json` |
| 权限能力 | `backend/app/core/permissions.py` + 数据库授权 | `backend/scripts/check_permission_drift.py`；权限矩阵自动块 | 引用生成块 |
| 后端测试结果 | CI 实际运行 | `backend-ci` 的 `backend-test` job + JUnit artifact | CI run URL / artifact |
| 前端检查结果 | CI 实际运行 | `backend-ci` 的 `frontend-check` job | CI run URL |
| E2E 结果 | CI 实际运行 | `backend-ci` 的 `frontend-e2e-mock` job；真实后端 E2E 单独记录 | CI run URL |
| 种子目录（AI 平台、入口、渠道等） | 实际 seed 脚本 + 目标库 | `backend/scripts/seed.py`、`seed_platform_catalog.py`、`seed_platform_api_entries.py`；目标库查询 | release manifest / 部署验收输出 |
| 工具链版本 | 仓库版本文件 | `.python-version`、`.nvmrc`、`frontend/package.json#packageManager` | CI 读取同一来源；文档只写策略 |

## 三、生成物与校验命令

在仓库根目录：

```powershell
.\backend\.venv\Scripts\python.exe -m alembic heads
.\backend\.venv\Scripts\python.exe -m alembic history --verbose
.\backend\.venv\Scripts\python.exe -m alembic check
.\backend\.venv\Scripts\python.exe backend\scripts\check_migration_immutable.py --base origin/main
```

在 `backend` 目录：

```powershell
.\.venv\Scripts\python.exe scripts\audit_schema.py
.\.venv\Scripts\python.exe scripts\audit_schema.py --check
.\.venv\Scripts\python.exe scripts\check_schema_ddl.py --target $env:DATABASE_URL
.\.venv\Scripts\python.exe scripts\audit_capability.py --check --strict
.\.venv\Scripts\python.exe scripts\check_permission_drift.py --doc ..\docs\权限矩阵.md
.\.venv\Scripts\python.exe scripts\export_openapi.py --check
.\.venv\Scripts\python.exe scripts\check_doc_baseline.py
.\.venv\Scripts\python.exe -m pytest -q --junitxml=..\artifacts\backend-junit.xml
```

发布与部署版本：

```powershell
# manifest 只由 .github/workflows/release.yml 在 tag checkout 内生成，本地不生成
python deploy\scripts\verify_release.py --manifest deploy\releases\<tag>.json
```

`release.yml` 以 annotated `v*` tag 为唯一入口，自动获得 token、干净 checkout、GHCR digest；本地只做部署核验，不构建 Release。发布变量和可选分支保护的操作口径见 `docs/发布版本治理.md`。

## 四、发布版本变量

| 变量 | 定义 | 不得混用 |
| --- | --- | --- |
| `CURRENT_MAIN` | 当前开发主分支 HEAD | 不是发布版本，不能作为生产构建输入 |
| `RELEASE_COMMIT` | annotated `v*` release tag 指向的固定 commit | 不能使用浮动分支 HEAD |
| `IMAGE_DIGEST` | release manifest 的 `repo_digest` | 不能用镜像 tag、本地 Image ID 或 label 代替 |
| `DEPLOYED_COMMIT` | 生产运行容器 label 中记录的实际 commit | 不能用 release manifest 代替实际检查 |

发布时由 `release.yml` 在 tag checkout 内生成 manifest，作为 GitHub Release asset 与 Actions artifact 附加，不提交主分支。部署前必须同时核对容器 `org.opencontainers.image.revision` label 与 `RepoDigests`；digest 是跨主机权威身份。

## 五、历史文档

`docs/冻结基线.md`、测试报告中的旧章节、旧交付记录、旧工作日志均为历史记录，只作审计对照，不作为当前判断依据。历史值不得被当前交付表、README、部署模板引用为“当前值”。

## 六、变更规则

- 修改迁移：必须新增迁移文件，禁止修改、删除、重命名已合并迁移。
- 修改结构：先生成并提交 `docs/表结构核对表.md` 与 `docs/数据库DDL.sql`，再让 CI 校验。
- 修改接口：重新导出 `docs/openapi.json`，不得手工改 JSON。
- 修改权限：只改 `permissions.py` 与迁移/种子，再重新生成权限矩阵块；不得同时维护第二套权限表。
- 修改部署版本：只改 release tag、manifest 与容器 label，不得把 commit 写死到部署模板。
