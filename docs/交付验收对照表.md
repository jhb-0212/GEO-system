## 附：角色权限与 seed 验收说明（2026-11-13）

### 1. 运行时权限与初始化是两层

- 运行时 `backend/app/services/access.py::role_permission_codes`：先按角色查 `role_permissions` 表；**该角色在表里的映射集合为空时**，才回退到 `app/core/permissions.py` 的代码矩阵。因此“只跑迁移、不跑 seed”的库会出现“部分角色有表映射、部分角色回退”的混合状态，不能当成权限已初始化。
- 初始化 `backend/scripts/seed.py::seed_role_permissions`：按矩阵逐条比对，只补缺失的 `(role_id, permission_id)`，**只增不删**。已有角色能力不会被覆盖。
- RBAC 迁移 `3f9c1d2e4b57` 只建表和 `sys_admin` 角色行，不插入任何角色—能力映射；没有数据迁移。
- 生产 `migrate` 一次性服务执行 `alembic upgrade head && python scripts/seed.py`，可幂等补齐；CI / 本地库若只跑迁移不跑 seed，会复现 403，这是预期行为，不是接口缺陷。
- 本期不新增迁移。将来若从代码矩阵**删除**某个能力，旧 `role_permissions` 行仍会授权；那种场景必须配套数据迁移清理旧映射，不能只改代码矩阵。

### 2. seed 账号范围

- `seed.py` 创建 `geo_admin`（`is_system_admin=true`，同时以 `project_admin` 加入 `gz-base`）。
- 同一 seed 幂等补 `geo_editor`（editor）、`geo_reviewer`（reviewer）、`geo_lead_ops`（lead_ops）、`geo_viewer`（viewer）四个项目角色账号，均 `is_system_admin=false`。
- 生产必须显式设置 `SEED_ADMIN_PASSWORD` 与 `SEED_USER_PASSWORD`；开发默认口令分别为 `geo-admin-dev` / `geo-user-dev`。已存在账号只补缺失的项目成员关系，不改密码、不改 `display_name`；本地开发库手工插入的 `geo_editor`（`display_name=「B4 联调 editor」`）不会被覆盖。
- 临时库实测：全新库第一次 `角色账号 +4（项目角色成员 +4）`、第二次 `+0`；账号为 `geo_admin/geo_editor/geo_reviewer/geo_lead_ops/geo_viewer`，成员角色分别为 `project_admin/editor/reviewer/lead_ops/viewer`。

### 3. `geo_admin` 权限口径更正

`geo_admin` 是项目管理员（`project_admin`），`/me` 实测 **15 个权限**，不是“只读 + 成员管理、无写能力”。准确清单：

- 成员管理：`project.member.manage`
- 全项目只读：`project.read`、`question.read`、`monitoring.read`、`evidence.read`、`content.read`、`publish.read`、`channel.read`、`lead.read`、`stats.read`
- 写/审批/导出/审计：`channel.write`、`content.review`、`evidence.review`、`export.data`、`audit.read`

仍缺：`content.write`、`publish.execute`、`monitoring.execute`、`question.write`。因此项目管理员能改渠道台账、审批内容与证据、导出数据，但不能写正文、不能执行发布、不能触发采样、不能维护题库。此前“只读 + 成员管理、无写能力”的说法作废。
