# 生产部署交付清单

> 目标：第 7 天把本地跑通的系统按本清单部署到生产，并留下可验收的证据。

## 一、部署拓扑

```
Internet ──443/80──> nginx（仅此服务暴露端口）
                       ├─ /api/, /health, /docs ──> api:8000（FastAPI）
                       └─ /                      ──> frontend:3000（Next.js）
api / worker ──> postgres:5432、redis:6379（仅容器内网，不映射宿主机端口）
```

## 二、生产编排要点（`deploy/docker-compose.prod.yml`）

| 要求 | 落地方式 |
| --- | --- |
| 数据库不对外 | `postgres` 服务**没有** `ports`，只在 `internal` 网络内可达 |
| Redis 不对外 | 同样不写 `ports`，并启用 `requirepass` |
| 仅 Nginx 暴露 | 只有 `nginx` 服务写 `80:80` / `443:443` |
| 密码来自环境 | `deploy/.env.prod`（不提交），DB / Redis 密码与 `SECRET_KEY` 全部外部注入 |
| 容器自愈 | 全部 `restart: always` + healthcheck + `depends_on: condition: service_healthy` |
| 数据持久化 | `pgdata`、`redisdata` 命名卷；备份落 `deploy/backups` |

## 三、上线步骤

1. `cp deploy/.env.prod.example deploy/.env.prod`，填写强密码、域名与 `SEED_ADMIN_PASSWORD`（**留空会被脚本拒绝**）。
2. 证书放入 `deploy/nginx/certs/`：`fullchain.pem`、`privkey.pem`（不提交仓库）。
3. 构建镜像（国内网络需指定 pip / npm 源，否则拉包会 SSL 中断）：
   `docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`
4. `docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod up -d`
   —— 其中的 `migrate` 是一次性服务：`alembic upgrade head && python scripts/seed.py`，成功后退出；`api` / `worker` 用 `service_completed_successfully` 等它结束，**不需要再手工跑迁移和种子**。
5. 验收：`curl -f https://<域名>/health`、`/health/db`、`/health/redis`，浏览器打开首页。
6. 首次备份：`deploy/scripts/backup_db.ps1`（生产把容器名换成 compose 生成的 postgres 容器）。

## 四、安全项

| 项 | 要求 |
| --- | --- |
| SSH | 仅密钥登录，禁用密码；`sshd_config` 限制 `AllowUsers` 与来源网段；改默认端口可选 |
| 防火墙 | 仅放行 22（限来源 IP）、80/443；5432/6379 一律不放行 |
| 密钥 | `SECRET_KEY` 随机 32 字节以上；数据库/Redis 密码不复用；`.env*` 不进仓库 |
| 传输 | 强制 HTTPS + HSTS；后端只信任 `X-Forwarded-Proto` |
| 凭证 | 发布账号凭证只存 `credential_ref`（引用），明文在专用密钥管理里，禁止落日志、落仓库、进前端 |
| 审计 | 导出、删除、权限变更、审批、发布、证据下载全部写 `audit_logs` |
| 上传 | `client_max_body_size 20m`，文件类型与大小在应用层再校验一次 |

## 五、监控与告警

| 监控项 | 阈值/动作 |
| --- | --- |
| `/health`、`/health/db`、`/health/redis` | 5 分钟一次，非 200 连续 2 次告警 |
| 容器状态 | `docker compose ps` 异常即告警 |
| 磁盘 | 使用率 > 80% 告警（备份与证据文件占空间） |
| Celery 队列积压 | 队列长度 > 1000 或最老消息 > 10 分钟告警 |
| 5xx 比例 | 5 分钟内 5xx 超过 1% 告警 |

## 七、本轮未验证项（如实声明）

1. **公网域名与真实证书未验证**：本机用自签证书（`geo.example.com` / `localhost`）走通 TLS，生产需换成 CA 签发的 `fullchain.pem` / `privkey.pem`，并核对 HSTS 与证书链。
2. **PITR 未配置**：当前仅逻辑备份，RPO 依赖每日全量 + 手动补备。
3. **压测未执行**：1000 RPS 承诺基线需第 6 天按实际接口跑压测报告，本清单不含该结论。
4. **生产宿主机未验证**：所有验证都在 Windows + Docker Desktop 本机完成，Linux 主机上的防火墙、磁盘容量、WAL 归档路径需在部署机复测。

## 八、本机生产编排验证记录（2026-11-11）

环境：Windows 11 + Docker Desktop 29.9.3 / Compose v5.7.0，自签证书，`deploy/.env.prod` 使用随机密码（未入库）。

| 项 | 结果 |
| --- | --- |
| 镜像构建 | `geo-prod-api`、`geo-prod-frontend`、`geo-prod-migrate`、`geo-prod-worker` 全部构建成功（前端基础镜像由 node:22 升为 node:24-alpine） |
| 容器状态 | postgres / redis `healthy`，api / worker / frontend / nginx `Up`，migrate 一次性任务 `Exit 0` |
| 迁移 | migrate 日志完整跑完 `6244e674a083 → 460052748386 → 482fc59c5212 → 3f9c1d2e4b57 → 8d1e2f3a4b5c` |
| 种子 | 首次：角色 6、能力码 22、角色能力映射 52、引擎 4、项目 `gz-base`、渠道 39、问题 6、口径 3；复跑全部 `+0`（幂等） |
| 库结构 | 37 张表，`alembic_version` = `8d1e2f3a4b5c` |
| HTTP 链路 | `http://localhost/` → 301 跳 HTTPS；`https://localhost/` 200（前端 10144 字节）；`/health` 200；`/health/db` 200；`/docs` 200；`/api/v1/projects` 401（无令牌被鉴权拦截，符合预期） |
| 异步链路 | worker 日志 `celery@... ready`，无 broker 连接告警 |
| 安全 | 容器内 `id` 为 `uid=1000(appuser)`，非 root 运行 |
| 备份 | 容器内 `pg_dump -Fc` 落 `deploy/backups/geo-prod-drill.dump`（131591 字节），`pg_restore` 到临时库后 37 表 / 6 角色 / 39 渠道 / 22 能力码一致，临时库已删除 |

本轮同时修掉三个会让首次上线卡住的缺陷：

1. **api 镜像不含初始化步骤** → 新增 `migrate` 一次性服务（`alembic upgrade head && seed.py`），api/worker 等它成功再启动，避免"容器全绿但库是空的"。
2. **nginx 缓存上游容器 IP** → 改为 `resolver 127.0.0.11 valid=30s ipv6=off` + 变量 `proxy_pass`，重建 api 后无需重启 nginx（实测重建 api 后 502→200）。
3. **Celery 以 root 运行告警 + broker 启动竞态** → 镜像改为非 root 用户，`broker_connection_retry_on_startup=True`。

另记两处构建/运行注意事项：Docker Hub 直连被墙时需先把 `python:3.12-slim`、`node:24-alpine`、`nginx:1.27` 从可达镜像源拉下并 `docker tag` 成本地名称；pip / npm 源用 `--build-arg PIP_INDEX_URL` / `NPM_REGISTRY` 覆盖，默认仍指向官方源。
