## 一、目标与边界

验证 11.2 的业务闭环：

1. 项目内角色按能力码工作：`project_admin` / `editor` / `reviewer` / `viewer` / `lead_ops` 不多权、不少权。
2. 题目 → 轮次 → 批量监测任务 → 采样执行 → 证据/引用复核 → 内容审批 → 发布回执 → 看板导出的主链路可走通。
3. 跨项目数据绝对不串；`sys_admin` 不因系统身份自动读取项目业务数据。
4. 导出写审计，失败样本不计入分母，统计无样本返回 `null`。

**不在本文范围**：前端页面交互、真实 AI 平台采样质量、压测、真实主机部署。上述分别由 A、B、客户环境负责。

## 四、验收用例

### A. 认证、角色与项目隔离

| # | 用例 | 操作 | 预期 |
| --- | --- | --- | --- |
| A1 | 五个账号可登录 | 分别 `POST /auth/login`，拿 JWT，再 `GET /auth/me` | 200；`me` 返回用户、项目与角色；令牌可访问该项目 |
| A2 | editor 不能读线索 | editor 令牌 `GET /projects/{id}/leads` | 403 `insufficient_role` |
| A3 | lead_ops 只能碰线索 | lead_ops `GET /channels`；再 `GET /leads` | 前者 403，后者 200 |
| A4 | viewer 不能写 | viewer `POST /contents`、`POST /monitoring/tasks/{id}/execute` | 均 403 |
| A5 | reviewer 不改正文 | reviewer `PATCH /content-versions/{id}/body` | 403；`POST /review` 200 |
| A6 | 跨项目隔离 | 项目 A 的 editor 令牌访问项目 B 的 `channels` / `leads` | 403 `project_forbidden`，不返回 B 的任何数据 |
| A7 | sys_admin 不自动读项目 | `sys_admin` 未加入项目时访问 `channels` | 403 `project_forbidden`；加入项目后才按角色放行 |
| A8 | 越权写审计 | 触发 A2/A6 后查 `audit_logs` | 有拒绝记录，`reason` 可定位；不能只抛错不落审计 |

### B. 题库 → 轮次 → 监测任务

| # | 用例 | 操作 | 预期 |
| --- | --- | --- | --- |
| B1 | 建题并开版本 | editor `POST /questions` ×6（测试项目可用等价 Q01–Q06），每题再 `POST /questions/{id}/versions` | 6 题新建默认 `status=draft`、`current_version_no=1`；`audience/intent/priority` 可保存；旧版本不可改 |
| B1b | 技术基线已激活 | `gz-base` 已有 Q01–Q06 `active`（v2 `technical-baseline-v1`）；运营确认正式问法后追加 v3 | 6 题 `status=active`；v2 保留；新轮次使用 v3，旧轮次仍锁定 v2 |
| B2 | 批量生成任务 | editor `POST /monitoring/rounds`，再 `POST .../tasks/batch`（6 题 × 4 个 AI 平台） | 生成 24 条；`round_id + question_version_id + engine_entry_id + sampling_no` 唯一，`sampling_no=1`；响应 `complete=true`、`generated_task_count=24`、`created_task_count=24`、`reused_task_count=0` |
| B2a | 全量未激活明确提示 | 在测试项目另建 6 道 `draft` 题（不要使用已激活的 Q01–Q06）后执行 `POST .../tasks/batch` | 200 + `complete=false`；4 个 AI 平台时 `expected_task_count=24`、`eligible_expected_task_count=0`、`generated_task_count=0`、`inactive_question_count=6`、`inactive_question_ids` 为 6 个 UUID、`skipped_reason="inactive_questions"`；不生成 draft 任务 |
| B2b | 部分未激活 | 测试项目 4 题 active、2 题 draft，4 个 AI 平台执行批量生成 | 生成 16 条；`expected_task_count=24`、`eligible_expected_task_count=16`、`generated_task_count=16`、`inactive_question_count=2`、`complete=false`、`skipped_reason="inactive_questions"` |
| B2c | AI 平台不足 | 测试项目 6 题 active，但只有 3 个启用入口 | `engine_count=3`、`expected_task_count=18`、`generated_task_count=18`、`complete=false`、`skipped_reason="engine_entries_insufficient"`；不得静默按 24 格通过 |
| B3 | 批量幂等 | 对同一轮次重复 B2 | 不新增任务；返回既有记录；任务表仍 24 条；`created_task_count=0`、`reused_task_count=24`、`generated_task_count=24`、`complete=true` |
| B4 | 任务列表与过滤 | `GET /monitoring/tasks?round_id=&engine_entry_id=&status=pending` | 只返回匹配项；分页稳定，按 `created_at` 降序 |
| B5 | 触发采样 | editor `POST /tasks/{id}/execute` | 202 + `task_id`；`GET /tasks/{task_id}` 可轮询 |
| B6 | 并发触发拒绝 | 同一 `pending` 任务连续触发两次 | 第二次 409 `task_rejected`；只产生一次执行 |
| B7 | 非 pending 不可触发 | 对 `running` / `done` 任务再触发 | 409 `task_rejected` |
| B8 | reviewer 不能执行 | reviewer 调 B5 | 403 `insufficient_role` |
| B9 | 失败样本落状态 | 让一个任务失败（平台超时/验证码） | 业务样本 `status=failed` + `failure_code`；`GET /tasks/{id}` 最终 `failed`；不允许任务失败而业务仍 `running` |
