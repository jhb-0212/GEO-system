## 2. B7 渠道写接口

### 2.1 POST `/channels`

请求示例：

```json
{
  "code": "xiaohongshu-brand",
  "name": "小红书品牌号",
  "category": "content_platform",
  "status": "candidate",
  "primary_domain": "xiaohongshu.com",
  "notes": "品牌主账号",
  "aliases": ["old-xhs.example.com"],
  "is_active": true
}
```

字段约束：

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 项目内唯一，**不可修改**；只能小写字母、数字、连字符，`^[a-z0-9][a-z0-9-]*$`，≤64 |
| `name` | 是 | 1–128 字 |
| `category` | 是 | 枚举，见下方 |
| `status` | 否 | 默认 `candidate` |
| `primary_domain` | 否 | 纯域名，自动小写、去尾部点；不能带协议/路径/空格；≤255 |
| `notes` | 否 | ≤5000 字 |
| `aliases` | 否 | 域名数组，≤50 条；自动去重、小写 |
| `is_active` | 否 | 默认 `true` |

`category` 枚举：

```text
own_site            自有站点
content_platform    内容平台
video               视频平台
community           社区
encyclopedia        百科
local_media         地方媒体
industry_media      行业媒体
institution         机构
```

`status` 枚举：

```text
candidate           候选
published           已发布
observed            已观测
review_pending      待归类 / 待复核
```

成功响应 201：

```json
{
  "data": {
    "id": "uuid",
    "code": "xiaohongshu-brand",
    "name": "小红书品牌号",
    "category": "content_platform",
    "status": "candidate",
    "primary_domain": "xiaohongshu.com"
  }
}
```

### 2.2 PATCH `/channels/{channel_id}`

只传要改的字段，未传保留原值；**不要传 `code`**。

```json
{
  "name": "小红书品牌号-新",
  "category": "video",
  "primary_domain": "new-xhs.example.com",
  "status": "observed",
  "notes": "更新后的备注",
  "is_active": true
}
```

服务端行为：

- 改名或换主域名时，旧名称、旧主域名自动保留为别名，前端不需要自己处理
- `notes` 不传保留；显式传 `null` 清空
- `aliases` 是**追加语义**；传 `[]` 不会清空已有别名
- 主域名或别名被别的渠道占用 → 400 `channel_domain_conflict`
- 成功响应 200，返回同上 `ChannelData`

### 2.3 B7 错误码

| HTTP | code | 前端处理 |
|---|---|---|
| 400 | `channel_code_conflict` | code 重复，定位到 code 字段 |
| 400 | `channel_domain_conflict` | 主域名/别名冲突，提示换域名 |
| 400 | `channel_conflict` | 并发或唯一键兜底冲突，提示重试 |
| 400 | `invalid_channel_field` | 必填字段被清空 |
| 403 | `insufficient_permission` | 无 `channel.write`，隐藏编辑入口 |
| 403 | `project_forbidden` | 项目无权访问，或渠道不属于当前项目 |
| 422 | `validation_error` | 字段格式错误，按后端 message 展示 |

## 3. B8 统计接口

### 3.1 看板三接口

`GET /stats/overview`：

```json
{
  "data": {
    "valid_answers": 24,
    "brand_mentioned_answers": 12,
    "citation_answers": 8,
    "brand_mention_rate": 0.5,
    "citation_rate": 0.3333,
    "channel_count": 5,
    "page_count": 7,
    "excluded": {
      "failed": 2,
      "manual_review": 1,
      "pending_or_running": 3
    }
  }
}
```

`GET /stats/by-engine`、`GET /stats/by-question` 返回 `data: []` 列表。

前端注意：

- `brand_mention_rate` / `citation_rate` 可能是 `null`，无有效回答时显示 `--`，不要显示 0
- `excluded.failed`、`excluded.manual_review`、`excluded.pending_or_running` 要单列，不能混进有效率分母

### 3.2 筛选参数

四个统计接口和导出共用：

| 参数 | 说明 |
|---|---|
| `round_id` | UUID，监测轮次 |
| `engine_id` | UUID，引擎 |
| `question_id` | UUID，题目 |
| `start_at` | ISO 8601 时间下限 |
| `end_at` | ISO 8601 时间上限 |

### 3.3 `GET /stats/export`

- 返回 `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename="stats-{project_code}-{timestamp}.csv"`
- 必须带 Bearer token，所以**不能用普通 `<a href>` 下载**，要用 `fetch` + `response.blob()` + `URL.createObjectURL`
- 导出会写 `export` 审计；前端不需要额外调审计接口

CSV 列固定：

```text
record_type,code,name,question_type,valid_answers,brand_mentioned_answers,
citation_answers,brand_mention_rate,citation_rate,channel_count,page_count,
failed_answers,manual_review_answers,pending_or_running_answers
```

`record_type` 规则：

- `overview`：始终 1 行
- `engine`：有有效样本的引擎各 1 行
- `question`：有有效样本的题目各 1 行
- **空项目只有 `overview` 一行**，前端解析不要假设一定有三段
- 无有效回答时，CSV 里的 rate 是空字符串，解析成 `null`，不要转 0

## 4. 前端页面落地建议

### 4.1 渠道台账列表 / 编辑

- 列表列：`code`、`name`、`category`、`status`、`primary_domain`
- 新增/编辑表单：
  - `code` 编辑时禁用
  - `category` / `status` 用枚举下拉
  - `aliases` 用 tag 输入
  - `notes` 用 textarea
  - `is_active` 用开关
- 保存成功 toast 提示“旧名称/旧域名已保留为别名”
- 域名冲突直接定位到 `primary_domain` 字段

### 4.2 统计看板

- 顶部卡片：有效回答、品牌提及率、引用率、渠道数、页面数
- 单独展示失败样本、待复核、未完成
- 分引擎表、分问题表
- 导出按钮带当前筛选条件

### 4.3 联调顺序

1. 登录拿 token
2. GET `/channels` 验证列表和分页
3. POST 新增一条测试渠道 → PATCH 改分类/名称 → 列表核对
4. GET `/stats/overview`、`/by-engine`、`/by-question`
5. GET `/stats/export` 用 blob 下载并解析 CSV
6. 用 viewer / editor / project_admin 各跑一次，确认按钮和 403 兜底

## 5. 交接补充：契约缺口与联调注意

### 5.1 渠道详情已回显编辑字段（#28 已合入）

`GET /channels/{channel_id}`、`POST /channels`、`PATCH /channels/{channel_id}` 现在都返回：

```text
id, code, name, category, status, primary_domain
notes, is_active, aliases
```

`aliases` 结构：

```json
{
  "notes": "...",
  "is_active": true,
  "aliases": [
    {"domain": "old.example.com", "alias_name": "旧渠道名"}
  ]
}
```

前端编辑已有渠道时可以直接回显这些字段，不再需要绕过详情接口。

### 5.2 别名只能追加，不能删除

`PATCH aliases: []` 不会清空已有别名，当前也没有删除别名的接口。  
如果前端需要“删除某个别名”，要么后端补删除语义，要么前端本期只做新增别名。

### 5.3 空项目导出不是固定三段

`/stats/export` 在空项目下只返回 `overview` 一行，这是当前测试覆盖的预期行为。  
前端 CSV 解析器要能处理 `engine` / `question` 段缺失，不要强制断言三段。

### 5.4 下载必须带 token

导出是受权限保护的接口，不能用静态链接直接下载。  
前端用 `fetch` 带 `Authorization`，拿到 `blob` 后创建临时下载链接。

### 5.5 域名冲突不要在 allowed 前端自行判断

前端只做基础格式校验（协议、路径、空格、长度）。  
主域名/别名是否被占用以后端 `400 channel_domain_conflict` 为准，避免前端缓存导致误判。
