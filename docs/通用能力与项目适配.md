# 通用能力与项目适配（2026-11-24）

目标：新接一个项目、换一个客户，**不改代码**就能跑；同一套代码在不同项目按各自口径出数。
实现方式只有三层，不做任何「自动猜客户口径」的智能。

## 四层结构（2026-11-24 增补客户主体与行业策略）

| 层 | 载体 | 说明 |
|---|---|---|
| 平台默认 | 代码常量（采集/发布/统计算法） | 与行业无关，任何客户共用 |
| 通用口径 | `project_policy.DEFAULTS` | 窗口、阈值、质量级别、SEO 必备标签 |
| 行业预设 | `industry_presets`（JSON 落库） | 术语、风险词、页型词表、基线题目 |
| 客户主体 | `organizations` | 客户一等公民，`projects.organization_id` NOT NULL |
| 项目策略 | `project_strategies` | 项目在预设上的差异，版本化只追加 |

`projects.code` 仍是**全局唯一**，不引入 per-organization 唯一域：项目编码带客户前缀（`edu-gz-01`）即可读，
按 code 查项目的所有现有入口（基线脚本、导入脚本、演示数据）零改动。

### 行业语义搬出代码

规则词表全部在 `seed_data/industry_presets/edu-training.json`，代码只保留算法：

| 原先硬编码 | 现在读自 |
|---|---|
| 质量门槛绝对化词、结果性数字词 | `quality.absolute_claims` / `quality.result_number_terms` |
| 高风险承诺词与错误文案 | `quality.guarantee_terms` / `quality.guarantee_message` |
| 事实类型中文标签 | `labels.fact_types` |
| 页型标签与词表 | `labels.page_forms` / `page_type.content_lexicon` / `page_type.title_keywords` |
| 引用页型判定词 | `page_type.citation_page_terms` |
| 首期基线 6 题 | `baseline_questions` |
| 启动材料口径标签与路线关键词 | `labels.startup_faq` / `startup.route_keywords` |

判据：`grep -E "就业|招生|校区|课程" backend/app` 命中 **0**。

### 项目换行业怎么做

1. 新行业写 `seed_data/industry_presets/<code>.json`；
2. 迁移或脚本把预设落 `industry_presets`；
3. 项目 `project_strategies` 指向该预设，仅在差异处写 `overrides`；
4. 跑测试：同一条内容在不同项目下应得到不同判定（`tests/test_industry_strategy.py` 已覆盖）。

### 未选行业时的行为（2026-11-24 修正）

默认预设由 `edu-training` 改为 `neutral`：

- `DEFAULT_PRESET_CODE = "neutral"`，中性预设无行业专属词表；
- 新建项目**不预选行业**，`GET /stats/industry` 返回 `selected=false` 与「未选择行业预设」提示；
- 中性预设没有基线题目，激活基线时**明确报错**，不借用其他行业那 6 题；
- 启动材料的路线关键词为空时不按关键词筛，避免用别的行业词误判缺项。

判据（测试）：`tests/test_industry_strategy.py` 覆盖未选行业显式报出、默认词表不含教育专属词。

### 不做的

- 不按 org 拆 code 唯一域；
- 不做 org 成员继承（等真有 3 个项目、同一批人反复加时再加 `organization_members`）；
- 不给新项目自动猜行业（预设必须人选）。

## 三层结构

| 层 | 载体 | 谁维护 | 变更影响 |
|---|---|---|---|
| 通用默认 | `backend/app/services/project_policy.py` 的 `DEFAULTS` | 研发 | 所有项目，除非被覆盖 |
| 项目口径 | `project_policies` 表（迁移 `e1a2b3c4d5f6`） | 项目管理员（`metric.manage`） | 只影响该项目 |
| 项目数据 | 各业务表，按 `project_id` 隔离 | 项目内角色 | 只影响该项目 |

读取一律走 `policy_value(db, project_id, key)`：没有配置行就回默认，**不产生隐式状态**，
也不会因为某项目没配过而报错。

## 口径键位（当前 6 个）

| 键 | 默认 | 谁在读 | 说明 |
|---|---|---|---|
| `freshness.window_months` | 18 | `services/content_freshness.py` | 内容多久算过期；契约页与新鲜度接口共用 |
| `contract.target_streak` | 30 | `services/acceptance_contract.py` | 连续采集目标天数 |
| `sentiment.min_report` | 50 | `sentiment_sampling.py` → 契约 | 共识条数不足不出正向率 |
| `quality.number_level` | `warn` | `services/content_quality.py` | 结果性数字无来源：warn / block |
| `quality.quote_level` | `warn` | 同上 | 直接引语无出处：warn / block |
| `seo.required_tags` | canonical、description、og:title、og:description、og:image、og:url、twitter:card、json-ld | `services/seo_audit.py` | 页面/微站必备标签清单 |

值类型在写入时校验：未知键、非法枚举、非正整数一律 `status=invalid` 并原样返回原因，**不落库**。

## 接口

- `GET /api/v1/projects/{id}/stats/policies`（`stats.read`）：返回生效值与通用默认，便于对照
- `PUT /api/v1/projects/{id}/stats/policies`（`metric.manage`）：批量覆盖，`value=null` 回默认；写审计 `stats.policies.update`
- 统计接口的 `months` / `target_streak` 参数默认值改为「不传即按项目口径」，显式传参仍然优先

权限收紧：`metric.manage` 从编辑角色移除，口径属管理权（需重跑 `scripts/seed.py` 才同步到既有库）。

## 质量门槛：数字与引语必须带来源

`run_quality_check(body, known_phones, *, number_level, quote_level)` 新增两类判定：

| 判定 | 命中条件 | 默认级别 |
|---|---|---|
| `number_unsourced` | `就业率/月薪/薪资/起薪` 等结果性数字，所在段无来源 | warn |
| `quote_unsourced` | 中文引号内 ≥6 字引语，所在段无出处 | warn |

「有来源」只认三种可核验形式，且必须与数字/引语同段：
URL、`来源：`/`出处：`/`引自` 标注、`据…报告/统计/数据/公示/通报` 表述。
不做语义猜测（不判断「看起来像来源」），跨段落引用不算有来源——这是刻意的严格。

级别由项目口径控制：某项目要求「无来源即打回」就把 `quality.number_level` 设 `block`，
其余项目保持 warn，互不影响。

## SEO 核验

- `GET /stats/seo-audit?slug=`：按微站数据推导将渲染的 head 字段，**站未上线也能核验**；
  没有 `site_sites` 实例时如实返回 `ok=false` 与原因，不假装通过
- `POST /stats/seo-audit/html`：任意页面 HTML（官网落地页、客户站、生成页）只读核验
- `og:image` 取站内模块第一个可访问图片；无图即报缺，不用占位图凑数
- 前端 `app/s/[slug]/page.tsx` 已补 `og:image`、`og:locale`、`twitter:card`，与后端同一取图规则

## 开通向导（2026-11-24 第 2 步）

`POST /projects/{id}/onboarding/preview`（只算不写）→ `apply`（确认后落草稿）；
可选预设走 `GET /projects/{id}/industry-presets`。工作台入口：配置与管理 → 监测与项目设置 → 开通向导。

要填的 8 个字段（5 分钟）：品牌名 + 别名、官网/自有域名、行业预设、地区、产品线 3–8、竞品 3–5（名+域名）、
目标引擎（可选）、问题条数 8–12（可自动生成）。

派生四样，全部是草稿：

| 派生 | 落库位置 | 状态 |
|---|---|---|
| 问题集（模板 × 品牌/产品/地区/竞品） | `questions` + `question_versions` | draft |
| 渠道清单（`preset.channels` 映射） | `channels` | candidate + pending_review |
| 策略（继承预设，阈值取通用默认） | `project_strategies` | active |
| 首轮计划（轮次 + 题目×引擎×样本） | `monitoring_rounds` / `monitoring_tasks` | planning / pending |

规则：
- 预设必填且必须存在，缺失返回 `onboarding_preset_required`，不静默用中性以外的行业；
- 无可用引擎入口时只建轮次、不建任务，并在 `warnings` 说明；
- 重复 apply 幂等：只补缺，不重复建题目/渠道/竞品，不换轮次；
- 不自动发起采集、不发布。

## 新项目接入步骤

1. 建项目（`project.create`）→ 得到 `project_id`，全部业务数据按此隔离
2. `GET /stats/policies` 看通用默认，判断哪些要改
3. `PUT /stats/policies` 只覆盖有差异的键，`notes` 写清为什么改
4. 跑一次 `GET /stats/seo-audit`、`GET /stats/acceptance-contract`、`GET /stats/content-freshness`，
   确认结构出得来（数据为空属正常，不写成 0）
5. 需要时再建微站、渠道、监测任务——这些是项目数据，不涉及代码

## 明确不做

- 不做合成分 / 综合分 / 加权总分；
- 不做自动推断客户口径（口径只能人配）；
- 不因「新项目」放宽验收数字口径（正向率等仍是双人共识 + 阈值）；
- 不自动发布到外部平台。
