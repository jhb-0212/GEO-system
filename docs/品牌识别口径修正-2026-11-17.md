# 品牌识别口径修正（品牌实体配置 + brand_identified）

日期：2026-11-17
关联：`docs/DeepSeek网页版落库验证-2026-11-17.md` 第五节「brand_mentioned 全为 false 的原因」（该文已随网页桥入口在 2026-11-17 一并删除，结论保留在此处）

## 一、为什么要改

11-17 落库验证里 6 题全部判 `miss`。判 miss 本身没错，问题在**口径**：

- 品牌词表取自 `[project.name, project.code]`，本项目是「广州基地 / gz-base」，是 seed 占位符，不是对外品牌名；
- Q01 答案给出了详细地址（番山创业中心1号楼2区2楼（或207室）、番禺大道北537号）和报名电话 13022038683（该号码来自 DeepSeek 转述的站外信息，官网未见，见第七节），但正文从头到尾没出现品牌名（用「这个实训基地」指代）；
- 所以「补别名」救不了这类答案——答案里压根没有品牌名可匹配；而「把地址电话塞进别名表」会把**提及率**污染成「提及或可识别率」，11-16 / 11-17 两轮历史数据立刻不可比。

同时另一处隐患：`monitoring_citations.is_brand_related` 在本轮 37 条引用里**全为 false**，因为项目没配自有域名，`apply_answer_payload` 的 `brand_domains` 参数虽已预留但两处调用点都没传——「信源占比 / 品牌自有渠道引用」这个 GEO 最可执行的指标一直是死的。

## 二、方案（三件事一次做完）

| # | 改动 | 作用 |
|---|---|---|
| 1 | 新表 `brand_profiles` | 品牌正式名 + 别名 + 唯一标识 + 自有域名，一个项目一份 |
| 2 | 样本新增 `brand_identified` | 答案含品牌唯一标识（地址/电话/公众号）时记 true |
| 3 | 采集与统计改读配置 | 三处硬编码品牌词收敛到一个来源；情感/位次也吃标识词 |

**`brand_mentioned` 的定义与语义完全不动**，保证 11-16 / 11-17 两轮数据仍可比。这是整个方案的硬约束。

## 三、三类词条的分工（不能合并）

| 词条 | 驱动字段 | 影响指标 | 取值原则 |
|---|---|---|---|
| `aliases`（正式名 + 别名） | `brand_mentioned` | 提及率（跨引擎、跨时间可比） | 只放名称类词条：全名、简称、旧名、英文名 |
| `identifiers`（唯一标识） | `brand_identified` | 可识别率（并行指标，不覆盖提及率） | 越精确越好：门牌/房号/电话/公众号名 |
| `owned_domains`（自有域名） | `is_brand_related` | 信源占比 | 不确定就留空，别猜 |

接口层直接拒绝「同一词条同时出现在 aliases 与 identifiers」（`brand_term_overlap`），因为那是两个指标的污染源。

**标识不能取得太宽**：`番禺节能科技园`、`番山创业中心` 这类园区/写字楼名里驻着许多公司，拿它当「唯一定位品牌的标识」会把别人的地址算成自己的可识别。首版只保留到房号/门牌/电话。

## 四、未配置时怎么办：回退，不放大

`build_vocabulary()` 的规则：

- 没有生效的 `brand_profiles` 行 → `mention_terms` 回退到 `[project.name, project.code]`、`identifier_terms` 与 `owned_domains` 为空、`configured=false`；
- 配了配置但 `is_active=false` → 同样视为未配置，回退；
- `identifier_terms` 为空时 `brand_identified` 恒为 false，不会凭空把 miss 变成 hit。

所以**没配的项目行为与改动前完全一致**，历史样本不受影响。

## 六、口径定义（已写进 `geo_overview.definitions`）

```
mention_rate    = brand_mentioned_answers / valid_answers
identified_rate = brand_identified_answers / valid_answers
                  （答案没点名但含地址/电话/公众号名等唯一标识；与 mention_rate 并行，不覆盖。
                    自有域名只影响 citation_share，不参与本指标）
sov             = brand_mentioned_answers / (brand_mentioned_answers + competitor_mentioned_samples)
```

`sov` 仍然只比「点名提及」，可识别不进 SOV 分子/分母——否则 SOV 会随标识词表宽窄漂移。

## 七、真实库验证（gz-base）

配置内容（`scripts/setup_brand_profile.py --apply` 落库）：

```
canonical_name = 广东省AI数字人才就业实训基地
aliases        = 广东省AI数字人才就业实训基地 / 广东省成才人工智能产业孵化有限公司 / 成才
identifiers    = 番山创业中心1号楼2区207 / 番山创业中心1号楼2区2楼 / 番禺大道北537号 / 19927547288
owned_domains  = gdccai.com
```

地址与电话按业务方要求「按官网的来」对齐 `www.gdccai.com` 原文：官网正文为「广州市番禺区东环街番禺大道北537号番禺节能科技园内番山创业中心1号楼2区207」，页脚联系电话为 `19927547288`。抓取该站首页时标题为「广东AI数字人才就业实训基地_AIGC实训_AI大模型就业培训_AI漫剧制作培训」，正文写明「由广东省成才人工智能产业孵化有限公司运营」——品牌名、运营主体、地址三处与已配置口径一致，故按原文录入而非猜测。

三处口径变更要留意：

- **电话换了。** 原配置的 `13022038683` 来自 11-17 那轮 DeepSeek 作答转述的站外信息，官网页面（首页正文与页脚）均未出现该号码，因此按官网改为 `19927547288`。如果那个号码确实是招生老师的工作号，需要业务方明确后再补回来，不能凭“答案里出现过”就当成品牌唯一标识。
- **房号按官网写成 207。** 「2区207」与「2区2楼」是同一间房的两种写法（207 在 2 楼）。官网用 207，而 11-17 那轮 DeepSeek 的原话是「…1号楼2区2楼（或207室）」，所以两种写法都保留——只按官网替换掉「2楼」会让已判定的历史样本凭空丢掉命中，那是用文案规范去改数据。
- 改写后重跑回填：样本 6 条，`brand_identified` 变更 0 条，Q01 仍为 `identified=True`，`identified_rate` 保持 0.1667。

按新口径回填历史样本的 `brand_identified`（**只回填这一个字段，`brand_mentioned` 不动**）：

| 指标 | 值 |
|---|---|
| valid_answers | 6 |
| mention_rate | 0.0（0/6，与 11-17 完全一致，证明历史提及口径未被改动） |
| identified_rate | 0.1667（1/6） |
| 可识别样本 | 仅 Q01 `2a7605f4-1f80-41f9-99f3-b42f661bbc83`（`mentioned=false` / `status=miss`） |

情感与位次也随配置修正：改动前 Q01 在情感维度记为 `not_mentioned`（等于整段无效），改动后计入 `neutral` 且 `brand_position.average_rank=1.0`。

**补上自有域名后信源占比仍为 0，这是事实而非配置问题。** 本轮 37 条引用的域名分布里没有任何一条来自 `gdccai.com`（逐条核对过，命中数 0），`is_brand_related` 因此保持全 false，`citation_share` 仍是 0.0。也就是说这一轮 DeepSeek 联网搜索**确实没有引用过公司官网**。配域名的作用是从下一轮采集起让该指标可判定，而不是把历史数字改好看。

注：`is_brand_related` 只在字段为 NULL 时按域名判定（见 `apply_answer_payload`），已落库的 false 不会被重放覆盖，所以历史引用不需要、也不应该回填——否则等于用今天的域名清单去改写过去那一轮的检索事实。

## 十、遗留与边界

1. **`project.name` 仍是占位符「广州基地」**。本轮不动它：它是项目名，不是品牌名；现在品牌识别已走 `brand_profiles`，占位符不再影响指标。是否改名属后台运维决策。
2. **自有域名已配 `gdccai.com`**，但本轮 37 条引用无一条来自该域名，`is_brand_related` 仍全 false、信源占比仍为 0。要从下一轮采集起才可能变化。若还想纳入公众号落地页等二级来源，需业务方给出具体域名再补。
3. **历史样本只回填了 `brand_identified`，未重算 `brand_mentioned`**。这是刻意的：重算会让提及率跨期不可比。若将来确需按新别名重算历史，必须同时给报表加「口径版本」标记，否则两轮数据会被误当作同口径对比。
4. **`brand_identified` 只是辅助信号，不是命中**。样本 `status` 仍严格由 `brand_mentioned` 决定（`hit`/`miss`），可识别不改写状态机。自有域名同理，不参与 `brand_identified`，只影响 `citation_share`。
5. 前端页只在真实接口模式（`mode=live`）可用，演示模式显示空态；这与工作台其他 workspace 组件一致。
6. **`13022038683` 已按官网口径移除。** 它是 DeepSeek 作答里转述的站外号码，官网首页正文与页脚都没有；现在 identifiers 用官网页脚的 `19927547288`。若该号码确为招生工作号，需业务方确认后补回并重跑回填。
7. **官网英文名未纳入识别**（`GUANGZHOU AI DIGITAL TALENT EMPLOYMENT TRAINING BASE`）。中文问答场景用不上，且英文长名做子串匹配容易误命中，暂不配置。
