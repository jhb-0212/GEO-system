# 品牌识别口径修正（品牌实体配置 + brand_identified）

日期：2026-11-17
关联：`docs/DeepSeek网页版落库验证-2026-11-17.md` 第五节「brand_mentioned 全为 false 的原因」

## 一、为什么要改

11-17 落库验证里 6 题全部判 `miss`。判 miss 本身没错，问题在**口径**：

- 品牌词表取自 `[project.name, project.code]`，本项目是「广州基地 / gz-base」，是 seed 占位符，不是对外品牌名；
- Q01 答案给出了详细地址（番山创业中心1号楼2区2楼、番禺大道北537号）和报名电话 13022038683，但正文从头到尾没出现品牌名（用「这个实训基地」指代）；
- 所以「补别名」救不了这类答案——答案里压根没有品牌名可匹配；而「把地址电话塞进别名表」会把**提及率**污染成「提及或可识别率」，11-16 / 11-17 两轮历史数据立刻不可比。

同时另一处隐患：`monitoring_citations.is_brand_related` 在本轮 37 条引用里**全为 false**，因为项目没配自有域名，`apply_answer_payload` 的 `brand_domains` 参数虽已预留但两处调用点都没传——「信源占比 / 品牌自有渠道引用」这个 GEO 最可执行的指标一直是死的。

## 二、方案（三件事一次做完）

| # | 改动 | 作用 |
|---|---|---|
| 1 | 新表 `brand_profiles` | 品牌正式名 + 别名 + 唯一标识 + 自有域名，一个项目一份 |
| 2 | 样本新增 `brand_identified` | 答案含品牌唯一标识（地址/电话/公众号）时记 true |
| 3 | 采集与统计改读配置 | 三处硬编码品牌词收敛到一个来源；情感/位次也吃标识词 |

**`brand_mentioned` 的定义与语义完全不动**，保证 11-16 / 11-17 两轮数据仍可比。这是整个方案的硬约束。

## 三、三类词条的分工（不能合并）

| 词条 | 驱动字段 | 影响指标 | 取值原则 |
|---|---|---|---|
| `aliases`（正式名 + 别名） | `brand_mentioned` | 提及率（跨引擎、跨时间可比） | 只放名称类词条：全名、简称、旧名、英文名 |
| `identifiers`（唯一标识） | `brand_identified` | 可识别率（并行指标，不覆盖提及率） | 越精确越好：门牌/房号/电话/公众号名 |
| `owned_domains`（自有域名） | `is_brand_related` | 信源占比 | 不确定就留空，别猜 |

接口层直接拒绝「同一词条同时出现在 aliases 与 identifiers」（`brand_term_overlap`），因为那是两个指标的污染源。

**标识不能取得太宽**：`番禺节能科技园`、`番山创业中心` 这类园区/写字楼名里驻着许多公司，拿它当「唯一定位品牌的标识」会把别人的地址算成自己的可识别。首版只保留到房号/门牌/电话。

## 四、未配置时怎么办：回退，不放大

`build_vocabulary()` 的规则：

- 没有生效的 `brand_profiles` 行 → `mention_terms` 回退到 `[project.name, project.code]`、`identifier_terms` 与 `owned_domains` 为空、`configured=false`；
- 配了配置但 `is_active=false` → 同样视为未配置，回退；
- `identifier_terms` 为空时 `brand_identified` 恒为 false，不会凭空把 miss 变成 hit。

所以**没配的项目行为与改动前完全一致**，历史样本不受影响。

## 六、口径定义（已写进 `geo_overview.definitions`）

```
mention_rate    = brand_mentioned_answers / valid_answers
identified_rate = brand_identified_answers / valid_answers
                  （答案没点名但含地址/电话/自有域名等唯一标识；与 mention_rate 并行，不覆盖）
sov             = brand_mentioned_answers / (brand_mentioned_answers + competitor_mentioned_samples)
```

`sov` 仍然只比「点名提及」，可识别不进 SOV 分子/分母——否则 SOV 会随标识词表宽窄漂移。

## 十、遗留与边界

1. **`project.name` 仍是占位符「广州基地」**。本轮不动它：它是项目名，不是品牌名；现在品牌识别已走 `brand_profiles`，占位符不再影响指标。是否改名属后台运维决策。
2. **自有所属域名仍为空**。项目目前没有已知官网/公众号，`owned_domains` 留空意味着 `is_brand_related` 仍全 false、信源占比仍不可用。要启用这个指标，需要业务侧给出真实域名（或公众号落地页域名）再填。
3. **历史样本只回填了 `brand_identified`，未重算 `brand_mentioned`**。这是刻意的：重算会让提及率跨期不可比。若将来确需按新别名重算历史，必须同时给报表加「口径版本」标记，否则两轮数据会被误当作同口径对比。
4. **`brand_identified` 只是辅助信号，不是命中**。样本 `status` 仍严格由 `brand_mentioned` 决定（`hit`/`miss`），可识别不改写状态机。
5. 前端页只在真实接口模式（`mode=live`）可用，演示模式显示空态；这与工作台其他 workspace 组件一致。
