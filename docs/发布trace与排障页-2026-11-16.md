# 发布侧 trace 与内部排障页（2026-11-16）

## 1. 本轮目标

补齐引擎网关 v1 之后仍缺的两个运营可用性缺口：

1. 发布侧 trace：把“轮次 → 任务 → 样本 → 引用 → 发布”串起来；
2. 内部排障页：让运营能直接看到失败任务、失败码、重试次数、耗时和 trace。

不做可售卖产品包装，不引入 Langfuse / litellm 整套平台；继续沿用现有 FastAPI + Next 工作台。

## 2. 发布侧 trace 口径

### 2.1 关联路径

现有数据模型没有从 `PublishTask` 直接回到监测链路的字段，唯一可用路径是：

```text
content_version_citations
  ├─ version_id  → publish_tasks.version_id
  └─ citation_id → monitoring_citations.id
                     └─ trace_id
```

### 2.2 继承规则

- 内容版本关联的 `monitoring_citations.trace_id` 去重后**恰好一条**：`publish_tasks.trace_id` 继承该值；
- 去重后**多条**：视为归属歧义，`trace_id` 保持 `NULL`，不随机挑一条；
- 去重后**零条**：`trace_id` 保持 `NULL`，属于正常情况（内容版本没有关联监测引用）；
- 不拿项目、轮次或任意一条监测 trace 冒充发布 trace。

### 2.3 代码与契约

- 迁移：`migrations/versions/9d3e5f7a1b20_add_publish_task_trace.py`，新增 `publish_tasks.trace_id` 与索引；老数据按“唯一 trace”回填；
- 服务：`backend/app/services/trace_chain.py::trace_for_content_version()`；
- 建单：`POST /publish/tasks` 返回 `trace_id`；幂等复用返回原任务 trace；审计 `publish.task_create` payload 记录 trace；
- 列表：`GET /publish/tasks` 返回 `trace_id`；
- 响应模型：`PublishTaskData`、`PublishTaskCreated`。

## 3. 内部排障端点

```http
GET /api/v1/projects/{project_id}/monitoring/diagnostics
```

权限：`monitoring.read`。

查询参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `status` | `failed` | 样本状态；默认只看失败 |
| `failure_code` | 无 | `login_blocked` / `timeout` / `access_blocked` / `captcha` / `rate_limited` / `other` |
| `page` | 1 | 页码 |
| `page_size` | 20 | 每页，最大 100 |

返回字段：

- 样本：`sample_id`、`sample_status`、`attempt_no`、`retry_count`（`attempt_no - 1`）、`sampled_at`、`finished_at`、`failure_code`、`failure_note`；
- 任务：`task_id`、`task_status`；
- 引擎/问题：`engine_code`、`engine_name`、`question_code`、`question_title`；
- 网关：`trace_id`、`latency_ms`、`total_tokens`、`estimated_cost_cny`、`gateway_version`。

`trace_id` 优先取样本自身，样本为空时回退到任务 trace。

## 4. 前端内部排障页

- 入口：工作台系统分组“内部排障”；
- 文件：`frontend/components/diagnostics-workspace.tsx`；
- 功能：默认列出失败样本；可按失败码筛选；展示任务状态、引擎、问题、失败码、重试次数、耗时、token、完成时间、trace；支持刷新与分页；
- 代理：`frontend/app/internal/workbench/data/route.ts` 新增 `kind=diagnostics`；
- 发布侧：`PublishingWorkspace` 任务列表与详情展示 `trace_id`；未继承时明确写“未继承（内容版本没有唯一监测引用 trace）”。
