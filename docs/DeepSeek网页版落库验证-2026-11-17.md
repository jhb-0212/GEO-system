## 二、入口切换

`backend/scripts/register_deepseek_websearch.py --apply --activate-websearch` 执行结果：

| 入口 | protocol | 切换后 is_active |
|---|---|---|
| DeepSeek 网页版智能搜索（新建） | `deepseek_websearch` | **true** |
| DeepSeek 官方 API | `openai_compatible` | false（被停用） |
| DeepSeek网页端（旧） | `custom` | false |

同一引擎只取一个有效入口（`_active_engine_entries` 按 `created_at` 取最早），因此网页版与官方 API 不能同时 active，切换是互斥的。

`build_entry_adapter` 验证结果：

```text
adapter: DeepSeekWebsearchAdapter
bridge_url: http://127.0.0.1:8099
engine: deepseek supports_search=True supports_citation=True
active count: 1
```

**修掉的一个 bug**：注册脚本原写法 `AiEngineEntry(supports_citation=True)` 报 `invalid keyword argument`——`supports_citation` 只存在于 `AiEngine`（引擎级能力声明），`AiEngineEntry` 只有 `supports_search`。改为写 `engine.supports_citation = True`。

## 五、brand_mentioned 全为 false 的原因

本轮 6 题全部判 miss，但 Q01 答案确实给出了基地地址（番山创业中心1号楼2区2楼、番禺大道北537号番禺节能科技园）与电话 13022038683。判 miss 的原因不在采集，而在**品牌词口径**：

- `execute_task` 的品牌词表取自 `[project.name, project.code]`，本项目的值是 `广州基地` 与 `gz-base`；
- 6 份答案文本里都不含「广州基地」这四个字（答案用「这个实训基地」指代，正文未复述基地全名）；
- 因此 `brand_mentioned=false` 是该口径下的**正确判定**，不是链路故障。

这暴露一个口径问题：**品牌词表只有项目名，没有真实品牌名**（如「广东省成才人工智能产业孵化有限公司」）。Q01 这类「答案描述了品牌实体但没复述品牌名」的情形，会稳定判 miss，导致命中率被系统性低估。

建议（未在本轮实施，需业务侧确认品牌词）：

1. 为项目补齐品牌别名表（品牌全名、简称、「成才」等），品牌识别改为匹配多词；
2. 或在报表侧把「答案含品牌地址/电话等唯一标识」作为辅助命中信号，与字符串命中分开呈现。

## 七、结论

1. 真实链路**可用**：网页版入口 → 桥 → 适配器 → 网关 → 样本/引用落库，6/6 成功，无失败样本。
2. `engine_model` 正确写为 `deepseek-websearch`，`raw_response` 完整保留桥侧 `session_url` 与 `searched_page_count`，可回溯到具体 DeepSeek 会话。
3. 引用解析正确：37 条全部落到 `monitoring_citations`，域名归一化无空值。
4. `brand_mentioned` 机制正常，但当前品牌词只有项目名，命中率会被低估——这是**口径问题，不是链路问题**，需业务侧补品牌别名后再评估真实命中率。
5. 本轮只跑 DeepSeek 单入口，18 个 custom 协议任务保持 pending；要得到可比基线，需先让其余 3 个入口具备可执行适配器。
