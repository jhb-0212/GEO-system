# 登录与前端接后端（2026-11-17）

> 起因：《GEO执行计划-详细对账_2026-11-17》第 2.2 节与第 7 节写着「`auth/login` 未实现（现靠 `dev_token.py` 顶替）」「前端 Next.js 骨架，未接后端」。本文先核实这两条是否成立，再补真实缺口。

## 1｜核实结果：两条断言都不成立

| 对账文档的写法 | 仓库实际 | 证据 |
|---|---|---|
| `auth/login` 未实现 | 已实现，且带失败限流与锁定 | `backend/app/api/auth.py`：`POST /login`（`login_throttle` 限流 + 触达阈值写 `auth.login_locked` 审计）、`GET /me`（返回用户与项目/角色/能力码）、`POST /password`（改密后 `token_version += 1` 让旧令牌立即失效） |
| 前端骨架未接后端 | 已接，且是单点 BFF 转发 | `frontend/app/login/page.tsx` → `POST /internal/session` → 后端 `/api/v1/auth/login`，令牌写 httpOnly cookie（`geo_workbench_session`，8 小时）；业务读写在 `frontend/app/internal/workbench/data/route.ts` 一个路由里转发 30 多个资源（GET/POST/PUT/PATCH/DELETE） |
| —— | 会话失效会自动跳登录 | `frontend/lib/workbench/client.ts`：401 或 `token_expired/token_invalid/token_stale/user_inactive` → 清 cookie + `location.replace("/login")` |

E2E 也证明这一层是通的：`workbench-read.spec.ts` 4 个用例真实登录三种角色跑真实后端（`4 passed`），不是 mock。

**结论**：这两条是旧信息（同一份文档还把「4 引擎只有元宝调通」写成结论，见附录，与实测相反）。真正缺的不是「有没有」，而是**改密没有前端入口**。

## 2｜补的缺口：修改密码入口

后端有 `POST /api/v1/auth/password`，前端此前完全没有入口（账号菜单只有「切换账号」「退出登录」）。补了三层：

| 层 | 文件 | 做法 |
|---|---|---|
| BFF | `frontend/app/internal/session/password/route.ts`（新增） | 读会话 cookie → 转后端 `/auth/password` → **用响应里的新 token 覆盖 cookie**。后端改密会 `token_version += 1`，旧 token 立即失效；不写回新 token 的话，用户改完密码会把自己登出 |
| 客户端 | `frontend/lib/workbench/client.ts` | `changePassword(current, next)`，错误码与文案沿用已有 `WorkbenchApiError` |
| 页面 | `frontend/components/workbench-app.tsx` | 账号菜单新增「修改密码」；弹窗含原密码 / 新密码 / 确认新密码，前端先校验（≥8 位、两次一致、不得与原密码相同），失败展示后端原文（如「原密码错误」） |

## 3｜实测（真实接口，非 mock）

用 `geo_reviewer` 走 BFF 完整一轮，最后恢复原密码：

| # | 动作 | 结果 |
|---|---|---|
| 1 | 登录 `geo_reviewer / geo-user-dev` | `{"data":{"mode":"live"}}` |
| 2 | 用错的原密码提交改密 | HTTP 400，`current_password_invalid`「原密码错误」——状态码与业务码如实透传 |
| 3 | 正确改密为 `GeoTest-2026` | `{"data":{"ok":true}}` |
| 4 | **改密后立即查会话** | `{"authenticated":true}` —— 证明新 token 已写回 cookie（旧 token 已因 `token_version` 失效） |
| 5 | 用新密码重新登录 | 成功 |
| 6 | 改回 `geo-user-dev` | `{"data":{"ok":true}}` |
| 7 | 原密码重新登录 | 成功（已恢复） |
| 8 | 用临时密码 `GeoTest-2026` 登录 | HTTP 401，已失效 |

页面侧（工作台，`geo_admin` 已登录）：

| 检查 | 结果 |
|---|---|
| 账号菜单 | 「切换账号」「修改密码」「退出登录」三项，`role=menuitem` |
| 弹窗 | `dialog "修改密码"`，三个 `input[type=password]`，取消 / 保存新密码 |
| 前端校验 | 两次新密码不一致 → 提示「两次输入的新密码不一致」（未发请求） |
| 关闭 | 点取消即关闭，页面状态不变 |

回归：`pytest tests/test_auth_api.py tests/test_credentials.py` 17 passed；`eslint .` 0、`tsc --noEmit` 0。

## 4｜未做

- **忘记密码 / 自助重置**：需要邮件或短信通道，本轮未要求，也没有通道配置。
- **改密后的强制重新登录**：当前策略是「当前设备续用新 token，其他设备失效」，与后端语义一致；如要改成「全部重新登录」，只需 BFF 不写回新 token。
- **账号锁定的人工解锁界面**：后端有失败锁定与审计，解锁目前靠管理员直接改库/脚本。
