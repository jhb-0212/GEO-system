# 前端分页与格式化收敛清单

> 背景：审查发现「分页取数、页脚页码、日期格式化」在同一工作台里存在多套实现（Q-02 / R-06）。
> 共享基座已建立，但只有部分面板接入，且没有约束阻止新面板继续复制旧写法。
> 本文档是这份工作的**唯一进度表**：新增面板前先看这里，改动面板后回来更新状态。

## 一、统一基座

| 能力 | 唯一实现 | 说明 |
|---|---|---|
| 分页取数 | `lib/workbench/use-paged-data.ts` | `page / total / loading / error / reload / refresh` 一套状态；`fetchPage` 必须是 `useCallback` 稳定引用 |
| 页脚 | `components/table-pager.tsx` | 单页与多页的计数文案统一为「共 N 条」；多页另加页码与上下页 |
| 日期 | `lib/workbench/format.ts`（`formatDateTime` / `formatDate`） | 统一 `zh-CN`、`hour12: false`，空值统一 `—` |
| 业务编号 | 数据库 `serial_no` + `lib/workbench/format.ts`（`formatSerialNo`） | 由数据库序列在创建时分配，列表/详情/筛选/分页均使用同一编号；前端只补足三位，不从页码或排序推导 |
| 审计对象 | `lib/workbench/format.ts`（`formatAuditTarget`） | 操作日志只显示业务对象类型，不展示 target UUID |
| 页大小 | `lib/workbench/client.ts`（`WORKBENCH_PAGE_SIZE` / `MEMBERS_PAGE_SIZE`） | 面板不得再写死 20 |

## 三、约束（新增面板必须遵守）

1. 列表取数只用 `usePagedData`，不得自建 `const [page, setPage]` 与 `useEffect` 取数。
2. 页脚只用 `TablePager`，不得手写「上一页 / 下一页」。
3. 页面上的任何时间展示只用 `formatDateTime` / `formatDate`，不得在组件里直接 `new Date(...).toLocaleString()`。
4. 页大小只从 `client.ts` 常量取，不得在组件里写数字。
5. 演示（mock）数据必须与真实数据走**同一套过滤与渲染**：只允许数据来源不同，不允许行为不同。
6. 列表编号只使用后端返回的持久化 `serial_no`，经 `formatSerialNo` 补三位；不得用数组下标、页码、`total-index` 或 UUID 片段生成编号。技术 ID 只保留在搜索框、复制入口或 tooltip 中。

## 四、推进方式

- 不批量重写：按「下次改动即替换」推进，改动哪个面板就把哪个面板那一行改成「已接入」。
- 每次替换后跑 `tsc --noEmit` 与 `eslint`，并在提交信息里写上本次替换的面板名。
- 目的不是对齐写法，而是让「页大小、总数口径、空态文案、日期格式」只有一份事实。

## 五、BFF 写请求的调用约束（R-16）

BFF（`/internal/**`）的写请求（POST / PUT / PATCH / DELETE）现在要求 `Origin` 与 `Host` 的 host:port 一致：

- 浏览器页面发起：正常通过；
- 无 `Origin` 的脚本 / CLI / 压测直接打 BFF：**一律 403**，这是设计行为；
- 已知识边界：极少数客户端（旧浏览器、剥离请求头的中转代理）在同源写请求里不发 `Origin`，同样会被 403。遇到先确认请求头是否被剥掉，不要加白名单；
- 需要脚本化写入的，请走后端 API（`/api/v1/**` + Bearer/Cookie），不要打 BFF；
- 新增内部调用前先确认走的是哪一层，不要用「加个白名单」的方式绕过校验。
