# 引擎网关 v2、golden set 与引擎健康矩阵（2026-11-16）

本轮对应路线里的 P0「引擎网关 v2」和 P1 的前两项：golden set 回归、成本/延迟面板。跨实体 trace 与情感/位置/竞品份额仍留到下一轮，本文最后列出边界。

## 1. 网关 v2

文件：`backend/app/services/engine_gateway.py`

- 版本常量：`engine_gateway_v2`。
- 新增参数：
  - `fallback_adapters`：同一引擎的备用入口列表，按顺序尝试；
  - `max_attempts`：单个适配器最大尝试次数，默认读 `settings.monitoring_gateway_max_attempts`；
  - `retry_backoff_seconds`：重试退避，默认读 `settings.monitoring_gateway_retry_backoff_seconds`。
- 重试条件：只重试适配器异常上 `retryable=True` 的失败（超时、429、5xx）；401/403、参数错误等非重试失败直接进入 fallback 或抛出。
- fallback 条件：主入口失败后，依次尝试备用入口；备用入口成功时 `payload.gateway_fallback_from` 记录主入口名称。
- 失败留痕：`trace_id`、`request_payload`、`latency_ms`、`gateway_attempts` 都挂在异常上，排障页仍能回答“卡在哪一步”。
- 回放：`collect_with_request` 传入留存请求体时，调用方不应同时传 fallback，避免用 A 模型的请求体打 B 模型。

调用侧：`backend/app/services/monitoring_collection.py`

- `build_fallback_adapters()` 只取同一引擎下其他启用的入口；没有第二个入口时返回空列表。
- `LazyEntryAdapter` 延迟到真正调用时才构建适配器并关闭客户端，避免主入口成功也泄漏连接。
- 注入测试适配器时不启用 fallback，保持单测可控。

配置：`backend/app/core/config.py`

- `monitoring_gateway_max_attempts: int = 2`
- `monitoring_gateway_retry_backoff_seconds: float = 1.0`

## 2. 引擎健康与成本矩阵

接口：`GET /api/v1/projects/{project_id}/stats/engine-health`

权限：`stats.read`

按入口返回：

| 字段 | 含义 |
| --- | --- |
| `engine_name` / `entry_name` | 引擎与入口 |
| `protocol` / `model_name` | 协议与模型名 |
| `entry_url_configured` | 是否配置入口地址 |
| `credential_configured` | `credential_ref` 指向的环境变量是否有值；不返回密钥 |
| `price_configured` | 是否配置了该引擎的输入/输出单价 |
| `task_count` / `sample_count` | 任务数与样本数 |
| `valid_answers` | `hit + miss` |
| `failed_count` / `failure_rate` | 失败数/失败率 |
| `avg_latency_ms` | 平均延迟 |
| `total_tokens` | token 合计 |
| `estimated_cost_cny` | 估算费用；未配单价时为 `null` |
| `last_sampled_at` | 最近采样时间 |
| `availability` | `healthy` / `degraded` / `failing` / `untested` / `no_credentials` / `no_endpoint` / `disabled` |

口径：

- 没有样本的入口也会返回，状态 `untested`，不会被过滤掉；
- `sample_count = 0` 时 `failure_rate` 为 `null`，不显示成 0%；
- 费用只按已配置单价估算，未配置单价的入口明确显示 `null`。

前端：`frontend/components/statistics-workspace.tsx`

- 统计看板新增 `stats_tab=health`「引擎健康」子标签；
- 顶部五个汇总卡：入口数、总样本、平均延迟、总 token、估算费用；
- 入口矩阵：引擎/入口、可用性、任务、样本、失败率、平均延迟、token、费用、最近采样；
- 缺单价显示“未配置单价”，未采样显示“未采样”。

## 3. golden set 回归

文件：

- `backend/tests/golden/engine_answers.json`
- `backend/tests/test_golden_engine_answers.py`

固定 3 组回答夹具：

1. 品牌提及 + 两条引用 + 两个竞品（带位置）；
2. 品牌未提及、无引用、无竞品；
3. 字符串引用 + 字符串竞品名。

断言：品牌提及、引用域名、竞品名与位置、`total_tokens`。CI 的 `pytest -q` 自动执行，不需要额外 workflow。
