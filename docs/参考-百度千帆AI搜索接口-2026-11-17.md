# 参考：百度千帆 AI 搜索（web_search）接口

来源：用户提供的文档片段（`<script id="API_DOC_DATA">` 内嵌 JSON），解析时间 2026-11-17。
用途判断见 §6——它不是大模型问答接口，接不进现有的「引擎采集」，但能补「发布后被检索」这一层。

## 1｜接口

| 项 | 值 |
|---|---|
| 方法 / 地址 | `POST https://qianfan.baidubce.com/v2/ai_search/web_search` |
| 鉴权 | `Authorization: Bearer <API Key>`（API Key 方式，非 AK/SK 签名） |
| 请求体 | `application/json` |
| 响应 | JSON；异常时 HTTP 仍可能为 200，靠响应体 `code` / `message` 判断 |
| 概述 | 按 query 搜全网实时信息，返回摘要与网页 URL 列表 |

## 2｜计费与配额

- 每月免费 **1500 次**，按天发放；超出走按量后付费（需先在控制台开通后付费）。
- 默认优先抵扣免费额度。
- 429 的三种错误码：`RATE_LIMIT_SEARCH_QPS`（每秒配额）、`QUOTA_USER_DAILY_FREE`（当日免费额度用尽且未开通后付费）、`BILLING_INSUFFICIENT_BALANCE`（欠费）。
- 版本 `edition` 影响计费：`standard`（默认）/ `turbo` / `pro`，三档价格不同。

## 3｜请求参数

必填两项：`messages`、`resource_type_filter`。

| 参数 | 类型 | 说明 |
|---|---|---|
| `messages` | object | 必填。仅支持单轮，多轮时只取最后一条 `content` |
| `messages.role` | string | `user` / `assistant` |
| `messages.content` | string | 查询文本，**不能为空，上限 72 字符（一个汉字算 2）**，超长只取前 72 |
| `resource_type_filter` | object | 必填。`[{type, top_k}]`；网页 `top_k` ≤ 50，视频 ≤ 10，图片 ≤ 30，阿拉丁 ≤ 5；默认只取 web 20 |
| `resource_type_filter.type` | string | `web` / `video` / `image` / `aladdin`（`turbo` 版仅支持 web） |
| `edition` | string | `standard`（默认）/ `turbo` / `pro` |
| `search_filter.match.site` | array | 站点内搜索，最多 100 个域名；文档标注“付费功能，目前限时免费” |
| `search_filter.range.page_time` | object | 按发布时间过滤：`gte`/`gt`/`lte`/`lt`，支持 `YYYY-MM-DD` 或 `now-1w/d` 这类表达式；起止需成对出现 |
| `search_recency_filter` | string | `week` / `month` / `semiyear` / `year` |
| `block_websites` | array | 屏蔽站点及其子站点 |
| `chunks_per_doc` | integer | snippet 最大 chunk 数 1–3，默认 3，仅 `turbo`/`pro` |
| `compliance_scene` | string | `domestic` / `abroad` / `auto`，仅 `edition=turbo` 生效 |
| `safe_search` | boolean | 是否开启安全搜索，默认 false |
| `query_policy.enable_rewrite` | boolean | query 改写，默认关，约增加 10–20ms |
| `query_policy.query_plan_type` | string | 传 `deep` 开启 query 拆解（beta，2–3 轮），仅 Pro 版 |
| `config_id` | string | query 干预配置 ID |
| `rank` / `vertical` / `highlights` | object | 文档标注“即将上线” |

请求示例（原文摘要）：

```json
{
  "messages": [{"content": "北京有哪些旅游景区", "role": "user"}],
  "search_source": "baidu_search_v2",
  "resource_type_filter": [{"type": "web", "top_k": 20}],
  "search_filter": {"match": {"site": ["tieba.baidu.com"]}}
}
```

> 注：原文示例里出现 `search_source`，但参数表里没有这一项，推测是示例残留；接入时以参数表为准，先不带该字段试探。

## 4｜响应字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `references` | array | 必填。命中结果列表 |
| `references[].id` | integer | 引用编号，从 1 开始 |
| `references[].url` | string | 网页地址 |
| `references[].title` | string | 网页标题 |
| `references[].date` | string | 网页日期 |
| `references[].type` | string | `web` / `image` / `video` |
| `references[].web_anchor` | object | 锚文本等网页详情 |
| `references[].icon` | string | 站点图标 |
| `references[].image` | object | 图片 `url` / `width` / `height` |
| `references[].video` | object | 视频详情 |
| `request_id` | string | 请求 ID，排查用 |
| `code` / `message` | string | 异常时返回；`InternalError`（服务内部）、`InvalidArgument`（参数错） |

## 5｜关键限制（接入前必须接受）

1. **单轮 + 72 字符上限**：`content` 超过 72 字符会被截断。我们题库里的问题经常超过这个长度，接入时需要截断或先改写。
2. **HTTP 200 也可能是错误**：必须读 `code` 字段，不能只看状态码。
3. **配额按天**：1500 次/月平摊到每天约 50 次，批量跑题库会很快耗尽。
4. **`site` 过滤是付费功能**（目前限免），未来可能收费。

## 6｜与 GEO 系统的关系（重要）

这个接口是**搜索引擎**，不是大模型问答接口。现有 `monitoring_collection`（接各 AI 平台拿回答与引用）接不进它，也不该拿它替代引擎采集。

它真正能补的是我们目前缺的一环：

```
发布 → 回执(published_url) → 【被搜索引擎收录/可检索】 → 被 AI 引用(monitoring_citations)
                                  ↑ 这一层现在是空的
```

三种接法对比：

| 方案 | 做法 | 价值 | 成本 |
|---|---|---|---|
| A 不做 | 维持现状 | — | 0 |
| B 发布可见性检测 | 对 `publish_receipts.published_url` 的标题/URL 做 `site:` 限定搜索，判断“发出去的页面能不能被搜到” | 直接把“渠道发了但没效果”拆成“没被收录”与“被收录但 AI 没引”两种原因，正好补 §9 里记的闭环缺口 | 1 个新脚本 + 1 张小表（检测时间、是否命中、排名位置），按天跑，免费额度够 |
| C 信源发现 | 按题库问题搜全网，统计高频域名，作为“AI 可能从哪取证”的候选池，与 `/stats/sources` 的真实引用做对照 | 能做“应出现 vs 实际出现”的差值分析，指导选渠道 | 每问题每天 1 次，题库大时配额吃紧；且需要新表与前端面板 |

**推荐 B**：改动最小、口径最干净，且直接回答“我们发布到底有没有进入搜索索引”。C 可以等 B 跑一段时间、确认配额够用后再做。

> **2026-11-17 更新：方案 B 已落地**。表 `publish_visibility_checks`、脚本 `scripts/check_publish_visibility.py`、接口 `GET /stats/publish-visibility`、页面「统计看板 → 发布可见性」均已可用；实测正例第 2 位命中、负例 0 条。细节见 `docs/发布可见性检测-2026-11-17.md`。

## 7｜接入前的确认项与结论

1. **API Key**：已配置在 `.env` 的 `QIANFAN_API_KEY`（与并行流「文心搜索」适配器共用同一个键），不入库、不打印。
2. **费用**：免费额度按天发放；当前库 `publish_receipts` 只有 1 条，按天跑完全够，后付费暂未开通也不影响。
3. **落表口径**：已建 `publish_visibility_checks`（`receipt_id`、`checked_at`、`matched`、`position`、`matched_url`、`query`、`site`、`result_count`、`request_id`、`error_code`），只追加不改历史。
4. **与现有归因的关系**：这一层只是诊断信息，**不参与 `channel_id` 归因**——归因仍只认 URL 精确匹配回执，避免又回到“搜到就算渠道效果”的老问题。
