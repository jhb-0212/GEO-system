# 状态迁移表（C 侧底座契约）

> 版本：2026-11-12  
> 实现：`backend/app/services/state_machine.py`  
> 测试：`backend/tests/test_state_machine.py`  
> 适用范围：监测任务、采样、轮次、发布任务、内容版本。  
> 数据库 `CHECK` 只保证状态值合法，**不保证迁移合法**；迁移合法性统一由本表 + `ensure_*_transition()` 负责。

## 一、总则

1. 同状态视为幂等，直接放行；不重复写审计。
2. 未在表中列出的边一律拒绝，返回 `409 task_rejected`。
3. 终态没有出边。失败重试必须新建任务或新的样本 `attempt_no`，不能把旧记录改回 `pending`。
4. 状态校验不等于并发控制：并发入口仍需条件 `UPDATE ... WHERE status IN (...)` 或 `FOR UPDATE`，两者不能互相替代。
5. API 端点、Worker、脚本写状态前都必须调用 `ensure_*_transition()`；创建记录时的初始状态可以直接赋值。
6. 迁移表变更必须同时改代码、改本表、改测试，走 PR 评审。

## 二、监测任务 `monitoring_tasks`

| 当前状态 | 允许迁移到 | 触发点 | 说明 |
| --- | --- | --- | --- |
| `pending` | `running` | `POST /monitoring/tasks/{id}/execute`、Worker 领取 | 原子抢占，只有一个请求成功 |

| `running` | `cancelled` | 运营取消 | 已启动但未完成 |
| `done` | — | — | 终态 |
| `failed` | — | — | 终态；重试新建任务 |
| `cancelled` | — | — | 终态 |

## 三、采样 `monitoring_samples`

| 当前状态 | 允许迁移到 | 触发点 | 说明 |
| --- | --- | --- | --- |
| `pending` | `running` | Worker 开始执行 | 记录 `sampled_at` |
| `pending` | `failed` | Worker 启动前失败 | 例如项目停用、参数非法 |
| `running` | `hit` | 品牌被提及且证据有效 | 计入有效分母 |
| `running` | `miss` | 品牌未被提及 | 计入有效分母 |
| `running` | `failed` | 登录/超时/拦截/限流等 | 不计入有效分母 |
| `running` | `manual_review` | 结果不确定 | 待人工复核 |
| `manual_review` | `hit` / `miss` | 人工复核 | 复核人写 `review_result` |
| `manual_review` | `failed` | 人工复核确认失败 | 写失败原因 |
| `hit` / `miss` / `failed` | — | — | 终态 |

重试：新建 `attempt_no + 1` 的样本，不复用旧样本状态。

## 五、发布任务 `publish_tasks`

| 当前状态 | 允许迁移到 | 触发点 | 说明 |
| --- | --- | --- | --- |
| `pending` | `publishing` | 新增发布 attempt，结果 success | — |
| `pending` | `failed` | 新增 attempt，结果 failed | — |
| `pending` | `cancelled` | 运营取消 | — |
| `needs_review` | `publishing` | 复核后重新提交 | — |
| `needs_review` | `failed` | 复核后确认失败 | — |
| `needs_review` | `cancelled` | 运营取消 | — |
| `publishing` | `published` | 回执确认成功 | 终态 |
| `publishing` | `failed` | 明确失败 | 终态 |
| `publishing` | `unknown` | 回执不明 | 先核实，不重发 |
| `unknown` | — | `verify` 接口尚未实现 | 当前禁止新增 attempt；核实后再决定 |
| `published` / `failed` / `cancelled` | — | — | 终态 |

> 当前代码只实现“新增 attempt”这条链；`receipts` / `verify` 端点尚未实现。`unknown` 在实现 verify 前保持终态，避免误重发。
>
> 新增 attempt 入口在读取 `publish_tasks` 时使用 `SELECT ... FOR UPDATE`，同一任务并发提交只有一个能通过；第二个请求等锁后看到 `publishing`，返回 409 `task_rejected`。并发证据见 `backend/tests/test_publish_attempt_concurrency.py`。

## 六、内容版本 `content_versions`

> 这一组是契约草案，当前代码只在审批时写 `approved` / `rejected`，尚未在每个写入点强制；接入前不改现有行为。

| 当前状态 | 允许迁移到 | 触发点 |
| --- | --- | --- |
| `draft` | `pending_review` / `archived` | 提交审批 / 归档 |
| `pending_review` | `approved` / `rejected` | 审批 |
| `approved` | `scheduled` / `published` / `needs_attention` / `archived` | 排期、发布、异常、归档 |
| `rejected` | `draft` / `archived` | 退回修改 / 归档 |
| `scheduled` | `published` / `needs_attention` / `archived` | 发布、异常、归档 |
| `published` | `needs_attention` / `archived` | 异常、归档 |
| `needs_attention` | `scheduled` / `published` / `archived` | 重新排期、修复、归档 |
| `archived` | — | 终态 |

## 七、接入要求

- **监测执行**：`POST /monitoring/tasks/{id}/execute` 只允许 `pending → running`；并发必须用条件 UPDATE，不能用“先读再改”。
- **B4 批量生成**：创建任务初始状态 `pending`；批量锁 `monitoring_rounds` 轮次行 `FOR UPDATE`，不是 `projects` 行锁。
- **B4 采样器/Worker**：写样本状态前调用 `ensure_sample_transition()`；写任务终态前调用 `ensure_task_transition()`；运行中任务不得被其他请求改回 `pending`。
- **审计**：关键迁移写 `audit_logs`，payload 至少包含 `from` / `to`；同状态幂等不重复写。
- **不引入触发器**：当前没有外部系统直接写库；应用层校验 + CI 测试足够。若将来出现直连写入，再评估数据库触发器。
