# 引擎网关 v1 交付说明（2026-11-16）

## 1. 这版做了什么

先切 DeepSeek 一条真实链路，把“结果、trace、原始请求/响应、耗时、token/费用、失败回放”做成内部可用的一层，不引入 litellm / Langfuse 整套平台，也不做对外分发的 SDK / MCP / demo。

边界：

- 重试仍由 Celery 任务级 `max_retries=3, countdown=30` 控制；
- 限流仍由 `EngineRateLimiter` 按引擎每分钟 6 次控制；
- 超时仍由适配器 `httpx` 客户端控制（当前本地/OpenAI-compatible 120s）；
- 网关 v1 只做进程内统一结果 + 留痕 + 回放；fallback 暂不做，因为当前只有 DeepSeek 一个可用入口，无法验证降级正确性。

## 2. 数据链路

`MonitoringTask.trace_id` 在批量建任务时生成（32 位 hex）；老任务在第一次执行时补。样本和引用沿任务继承，形成：

`轮次 → 任务(trace_id) → 样本(trace_id) → 引用(trace_id)`

新增字段：

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `monitoring_tasks` | `trace_id` | 串轮次/任务 |
| `monitoring_samples` | `trace_id` | 串样本 |
| `monitoring_samples` | `request_payload JSONB` | 回放请求体，不含 `Authorization` |
| `monitoring_samples` | `latency_ms` | 单次调用耗时 |
| `monitoring_samples` | `prompt_tokens / completion_tokens / total_tokens` | token 用量 |
| `monitoring_samples` | `estimated_cost_cny Numeric(14,6)` | 可选估算费用，未配价格时为空 |
| `monitoring_samples` | `gateway_version` | 当前为 `engine_gateway_v1` |
| `monitoring_citations` | `trace_id` | 引用直接可查 trace |

迁移：`7c1d9e2a4b60_add_engine_gateway_trace.py`，`down_revision=2fbc5b97e953`；已 `alembic upgrade head`，老数据按任务 id 去横线回填 trace，样本/引用继承。

## 3. 代码位置

- `backend/app/services/engine_gateway.py`：`EngineGateway.collect()` 统一结果，补 latency、token、费用、request_payload、trace、gateway_version；失败时把 request/latency 挂到异常上，保证失败样本也有排障信息。
- `backend/app/services/local_llm_adapter.py`：新增 `last_request_payload` 与 `collect_with_request()`；回放只替换请求体，Authorization 仍从当前环境变量取。
- `backend/app/services/monitoring_collection.py`：`execute_task()` 接网关；`_claim_sample()` 写 trace；失败样本写 request/latency；新增 `replay_sample()`。
- `backend/app/services/monitoring_batch.py`：批量建任务生成 trace，复用老任务补 trace。
- `backend/app/services/monitoring_extraction.py`：`AnswerPayload` 增加网关字段；`apply_answer_payload()` 回写样本与引用 trace。
- `backend/app/api/monitoring.py`、`backend/app/api/responses.py`：任务/样本/详情返回 trace、耗时、token、费用、请求体；新增回放端点。

## 4. 回放语义

`POST /api/v1/projects/{project_id}/monitoring/samples/{sample_id}/replay`

- 权限：`monitoring.execute`；
- 用该样本的 `request_payload` 新建一次 `attempt_no`，不重开原任务，不改原任务状态；
- 新样本独立落 `hit/miss/failed`，trace 继承原样本；
- 旧样本没有 `request_payload` 时，退回按当前题目重建请求，响应 `used_stored_request=false`，不把“换题重跑”说成回放；
- 写审计 `monitoring.sample.replay`。

## 7. 明确没做

- fallback：只有 DeepSeek 单入口，做了也无法验证；等第二个可用入口（文心欠费解除 / 豆包接入点 / 元宝 SearchPro 开通）再补；
- 内部排障页：当前只有 API 字段和 trace 链路，没有前端页面；下一步做一个“失败任务 / 失败码 / 重试次数 / 耗时 / trace”列表；
- 价格表：只预留 `estimated_cost_cny` 和两个环境变量，没有把 DeepSeek 官方价格写死；配价后才会产生费用；
- 24 格回归：本次仍是 1/4 平台 6 格，不能写成 24 格完成；
- 发布侧 trace：发布任务/回执尚未挂到监测 trace，当前 trace 只到引用。
