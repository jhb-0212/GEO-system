# 引用复核操作口径（2026-11-17）

## 一、为什么这一步不能省

`stats.py` 的引用率定义是：

> 引用率 = 含品牌相关**且已人工复核（`review_status='manual_confirmed'`）**来源链接的有效回答 ÷ 有效回答

去重页面数、渠道数同样只数已确认的引用。而库里实况是：

```
39 条引用 → review_status 全部 auto，0 条 manual_confirmed
工作台「citation_rate / page_count / channel_count」→ 结构性恒为 0
```

也就是说：**只要没人复核，这三个数永远是 0，和"有没有被引用"无关。** 基线跑完如果不复核，等于白跑。

## 二、怎么做（脚本：`backend/scripts/review_citations_bulk.py`）

复核接口 `PATCH /citations/{id}` 一次只处理一条，一轮 24 格基线会带出 40–60 条引用，页面上逐条点不现实。脚本把"逐条点"换成"按域名整批判"。

**第 1 步：看分布（不写库）**

```powershell
cd backend
$env:PYTHONPATH = "C:\Users\EDY\Desktop\GEO系统开发\geo-system\backend"
.\.venv\Scripts\python.exe scripts\review_citations_bulk.py
```

当前实测（2026-11-17，`gz-base`）：

```
待复核引用（review_status=auto）：37 条，来自 32 个域名
  zhuanlan.zhihu.com   5 条
  ldqxn.com            2 条
  其余 30 个域名各 1 条
```

**32 个域名分散 37 条引用**——这本身就说明引用极度碎片化，也解释了为什么渠道归因难有稳定结果。

**第 2 步：按域名小批试**

```powershell
.\.venv\Scripts\python.exe scripts\review_citations_bulk.py --domain zhuanlan.zhihu.com --as geo_reviewer
```

确认清单里是你要的那批，再落库：

```powershell
.\.venv\Scripts\python.exe scripts\review_citations_bulk.py --domain zhuanlan.zhihu.com --as geo_reviewer --apply
```

**第 3 步：按轮次/引擎/题目整批**

```powershell
.\.venv\Scripts\python.exe scripts\review_citations_bulk.py --round 2 --engine DeepSeek --question Q02 --as geo_reviewer --apply
.\.venv\Scripts\python.exe scripts\review_citations_bulk.py --domain example.com --as geo_reviewer --reject --apply
```

## 三、脚本守住的两条线

**权限**：`--as` 指定的操作人必须在本项目持有 `evidence.review`。实测判定：

| 账号 | 角色 | 结果 |
| --- | --- | --- |
| `geo_admin` | 系统管理员 | 允许 |
| `geo_reviewer` | reviewer | 允许 |
| `geo_editor` | editor | 拒绝（"没有 evidence.review 权限"，退出码 3） |
| `geo_viewer` | viewer | 拒绝 |
| `geo_lead_ops` | lead_ops | 拒绝 |

**审计**：每改一条写一条 `audit_logs`，`action="citation.review"`、`target_type="monitoring_citation"`，与接口同格式；payload 额外带 `source="bulk_script"` 与 `batch_id`，日后能分清"人工点的"和"批量确认的"。

状态机与接口一致：**只能 auto → manual_confirmed / manual_rejected**，不允许回写 auto。

## 四、不能做的事

**批量确认的语义是"这条引用确实来自我们核过的那个页面"，不是"这条引用提到了我们"。** 没看过的引用不要批量确认——那等于伪造复核记录，比不复核更糟（会让引用率看起来有数，但数是假的）。

`is_brand_related` 是另一件事，脚本不改它。当前 39 条全是 `false`，因为没有一条来自 gdccai.com。

## 五、交接顺序（与 B 的基线对接）

1. B 跑满 24 格，轮次标记 `is_baseline=true`（全项目只能有一个）。
2. 跑本脚本 dry-run，看新增引用的域名分布。
3. 由 `geo_reviewer` 按域名逐批判定归属（或按轮次一次判完）。
4. 跑 `stats` 看 `citation_rate` / `page_count` / `channel_count` 是否出数——这是第 1 周验收之外、真正让看板有意义的一步。
5. 抽查任意一条：`GET /monitoring/traces/{trace_id}` 应能从轮次追到原回答、原 URL 与计算分母。

## 六、验收

- 引用率分子非 0（或明确写出"本轮确实无引用"，而不是"未复核"）；
- `audit_logs` 里能按 `batch_id` 追回每一次批量复核；
- 权限拒绝有记录（`geo_editor` 尝试执行应被拦且不落库）。
