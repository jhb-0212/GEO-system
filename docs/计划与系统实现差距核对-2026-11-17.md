# 计划 vs 系统实现：差距核对（2026-11-17）

对照文档：`广州基地GEO执行与系统开发计划.md`（立项稿，首月双线排期）。
核对方式：逐条读代码（模型 / 枚举 / 统计服务 / 公开接口）+ 查真实库（`gz-base`）。

## 一、结论

**数据模型基本按计划建完了，差的是"把数据填进去"和"人做复核"。**

计划第 3 节的 P0 模块，字段层面几乎全部落地：题目版本锁定、引擎入口分四类、采样模式分联网/不联网、失败原因分登录阻断/超时/验证码、引用分自动/人工确认、内容分母稿/渠道稿与六态、发布任务带回执不明态。这些不是"待开发"，是"待使用"。

真正卡住的是三处：

1. **24 格基线只填了 6 格有效**（6/24）。
2. **引用率结构性恒为 0**——39 条引用全部是 `auto`，样本 0 条人工复核，而口径要求"已复核"。
3. **计划里的"公开站"已被 2026-11-17 的下线决策替代**——这不是缺口，是计划被新决策覆盖（理由见第四节，这个决策是对的）。

## 四、两个必须先说清的口径问题

### 1. 引用率现在是"结构性 0"，不是"真的没被引用"

计划的定义是：**引用率 = 含基地相关且已复核来源链接的有效回答 ÷ 有效回答**。

`stats.py` 严格执行了这条：分子只数 `monitoring_citations.review_status = 'manual_confirmed'` 的引用。

但库里实况：

```
引用 39 条 → review_status 全部 'auto'（0 条 manual_confirmed）
引用 39 条 → is_brand_related 全部 false
样本 已人工复核 0 条
```

**后果**：`citation_rate`、`page_count`、`channel_count` 三个数在口径上必然是 0——哪怕某天 AI 真的引用了官网，只要没人把那条引用点成"人工确认"，看板仍然显示 0。

这跟之前查到的"官网 69 页被引 0 次"是两件事：那个结论来自 URL 比对（是事实），而看板上的 0 有一部分来自"没人复核"（是流程缺口）。两个 0 混在一起，会让人误判成"官网完全没被引用"，进而把力气全压在补内容上。

**建议**：复核动作要么制度化（每轮采集后 24 小时内逐条确认引用），要么把 `auto` 也纳入可展示口径、并单独标注"未复核占比"，两条数并存。

### 2. 计划里的"公开站"：**已被决策废止，且不该恢复**

计划 P0 写的是"公开页可直接读正文、配 sitemap、canonical、目标爬虫放行"——指的是**我们自己的公开品牌站**。

但 2026-11-17 的决策（`docs/公开站下线与内容登记口径-2026-11-17.md`，提交 `9ce510b`）是：**geo 不做公开站，对外公开页归公司官网 `www.gdccai.com`**，理由三条：

1. 同一段课程文案挂在两个域名 → 重复内容，权重互相抵消；
2. 两份真源，公司站改一次、geo 侧不跟 → 文案开始漂移，谁改都怕漏；
3. geo 的公开页是静态构建产物，改一句话要重新发布，而公司站的发布节奏不归我们控。

**这个决策在本项目的语境下是对的，比计划原文更正确。** 补充一条更硬的理由（计划里没写）：GEO 要的是"AI 认这一个实体"。同一主体、同一地址、同一课程挂两个域名自称官方，AI 在消歧时没有更强的那个可依据，反而可能引用表述更弱的那个——`brand_identified` 的可靠性会被自家第二个站稀释。

**所以：不恢复公开站。** 系统里保留的两条对外通道就够用：

- `GET /api/v1/public/projects/{project_code}/faqs`（匿名只读，只返 `published`），供公司官网拉取生成 `FAQPage` 结构化数据；
- 事实口径以公司官网当期页面为准，geo 只做对齐，不维护第二份对外文案。

**遗留的真问题不是"要不要建站"，而是这条计划验收要改写**：把"公开页可匿名访问且独立 URL"改成"官网页面登记齐（`public_pages`）+ FAQ 匿名端点可用"。现在 8 条 FAQ 全是 `draft`，端点返回空——这才是要补的。

> 若将来确实需要在官网之外承载结构化事实，唯一不制造实体分裂的做法是**挂在主域名下**（`gdccai.com/faq/` 子目录或 `faq.gdccai.com` 子域），继承主域权重、同属一个主体；另开全新域名是最差选项。目前官网冻结，此路不通，也不必走。

## 六、按计划该先补什么（不依赖官网）

1. **补一次真正的基线轮**：把 6 题 × 4 引擎跑满 24 格，`is_baseline=true`。这是第 1 周验收的唯一硬条件，也是后面所有对比的锚。
2. **把复核变成动作**：跑完立刻逐条确认引用，让 `citation_rate` 不再是结构性 0。
3. **内容侧关联补齐**：把已有 2 条内容版本挂上目标词、题目、证据——否则"母稿-渠道稿-回执"这条链只有骨架。
4. **计划里那条"公开站"验收要改写，不是恢复**：改成"官网页面登记齐 + FAQ 匿名端点可用"。当前缺口是 FAQ 8 条全 `draft`、端点返回空。
