## 3｜findings（按严重度）

### M1 素材面板加载失败后 loading 永久为真
- 文件：`frontend/components/knowledge-live.tsx`
- 行：290、292–299
- 现象：`loading = loadedProject !== targetProject`，但 `.catch()` 只 `onNotice`，从不写 `loadedProject`。请求失败（后端 500、网络断、权限变化）后，列表一直显示「正在加载素材…」，且没有重试入口。
- 建议：在 `.finally()` 里 `setLoadedProject(targetProject)`；失败态另给一个「重新加载」按钮。
- severity medium / category bug / confidence high / basis in_context

### M2 上架/下架会连带提交未保存的表单编辑
- 文件：`frontend/components/knowledge-live.tsx`
- 行：214–224（`togglePublish`），142–157（`save` 的 PATCH 体）
- 现象：`togglePublish()` 直接 `await save(next)`，而 `save()` 提交的是当前 `draft` 的 question/answer/category/sort_order。用户改了问题没点保存、直接点「下架」，这些编辑会被一并写库；若同时改了问题导致校验失败，下架也会失败。
- 建议：状态切换单独发一次只含 `status` 的 PATCH（`updateFaq(id, { status: next })`），不要复用整表单保存。
- severity medium / category bug / confidence medium / basis needs_external_context（需确认产品是否接受「切状态顺带保存」）

### M3 统计页把 6 个接口捆在 Promise.all，`/stats/sources` 失败会清空整页
- 文件：`frontend/components/statistics-workspace.tsx`
- 行：44–46
- 现象：`Promise.all([overview, byEngine, byQuestion, engineHealth, geo, sources])`，`.catch` 里 `setOverview(null)` 并置全局 error。新增的 `/stats/sources` 只要在某个环境不存在（旧后端、反向代理未放行、权限码不一致），整张统计页就变成「统计加载失败」，原有 5 个面板的数据也一并丢掉。
- 建议：`statsSources` 单独 catch 降级为空数组 + 一条局部提示；或按 tab 懒加载，切到「信源分布」才请求。
- severity medium / category bug / confidence medium / basis needs_external_context（取决于是否总能保证新接口先于前端上线）

### M4 回刷在 `yield_per` 游标内 `flush`
- 文件：`backend/app/services/citation_attribution.py`
- 行：135–152
- 现象：`select(...).execution_options(yield_per=500)` 打开流式游标后，在迭代体内每 500 条 `db.flush()`。SQLAlchemy 的 `yield_per` 依赖服务端游标 / 分批结果集，迭代期间在同一 Session 上执行写语句（flush 产生的 UPDATE）属于官方不建议的组合，不同驱动下可能表现为游标提前关闭、重复行或直接报错。测试库数据量小（命中 0 条），这条路径没被真正压到。
- 建议：改 keyset 分批——按 `id > last_id` 每批 500 条查询、批内更新、批末 `flush` + `commit`，不在打开的游标上写库；或用 `db.execute(update(...))` 一条 SQL 按 url_key 结果集更新。
- severity medium / category bug / confidence medium / basis needs_external_context（需真实数据量复现确认）
- 佐证：当前库 `monitoring_citations` 39 条、`publish_receipts` 1 条，命中 0，这条路径尚未在大数据量下跑过。

### L1 FAQ 搜索的 `%` / `_` 未转义
- 文件：`backend/app/api/faqs.py`
- 行：71–73
- 现象：`keyword = f"%{q.strip()}%"` 直接拼进 `ilike`。用户输入 `%` 会匹配所有记录（等于搜索失效），输入 `_` 会匹配任意单字符；不是注入（参数仍走绑定），但搜索语义不对。
- 建议：转义为 `q.replace("%", "\\%").replace("_", "\\_")` 并保留 `ilike` 的 escape 字符，或直接用 `func.lower(question).contains(lower(q))`。
- severity low / category bug / confidence high / basis in_context

### L2 `backend.ts` 只判断了 `"error" in payload`，没校验 error 的形状
- 文件：`frontend/lib/workbench/backend.ts`
- 行：30–38
- 现象：非 2xx 且响应是 JSON 时，取 `payload.error` 直接读 `.code` / `.message`。若上游返回 `{"error": null}` 或 `{"error": "boom"}`（网关/中间件的简化错误体），会抛 `TypeError` 而不是 `BackendError`，页面提示变成英文的运行时错误，且 `status` 丢掉。
- 建议：加类型守卫 `typeof payload.error === "object" && payload.error !== null && typeof payload.error.code === "string"`，不满足就落到 `upstream_http_<status>` 分支。
- severity low / category bug / confidence medium / basis in_context

### L3 「信源分布」标签里的数字是本次 limit，不是域名总数
- 文件：`frontend/components/statistics-workspace.tsx`（72、119）、`frontend/lib/workbench/client.ts`（315）
- 现象：`statsSources(projectId, limit = 10)`，tab 徽标与面板标题写 `sources.length`，文案是「{n} 个域名」。当前 dev 库正好 10 个域名，看起来是全部；域名超过 10 个时会显示「10 个域名」，且没有「还有更多」的提示。
- 建议：徽标写成「前 10 个」，或接口返回 `total` 一并展示；面板底部加「仅显示引用最多的 10 个域名」。
- severity low / category bug / confidence high / basis in_context

### L4 FAQ 每页条数 20 硬编码三处
- 文件：`frontend/components/knowledge-live.tsx`
- 行：94（请求 `pageSize: 20`）、239（`Math.ceil(total / 20)`）、242（`page * 20 >= total`）
- 现象：同一常量散落三处，改一处分页就会算错；且 117 行 `const visible = items` 是纯别名，没有过滤作用，容易误读成「前端过滤仍在」。
- 建议：提取 `const PAGE_SIZE = 20`，三处引用同一常量；删掉 `visible` 或在需要前端过滤时再引入。
- severity low / category style / confidence high / basis in_context

### I1 `build_published_index` 的注释与实现不符
- 文件：`backend/app/services/citation_attribution.py`
- 行：75–95
- 现象：docstring 写「不把整行 ORM 对象装进内存」，实现上确实只取了 6 列，但末尾 `.all()` 仍把全部回执行物化成一个 list 再建字典，回执量大时是全量驻留。措辞容易让人以为已经做了流式。
- 建议：改成「只取归因所需列，不加载整行 ORM 实体」，或直接 `.tuples()` 迭代建索引。
- severity info / category style / confidence high / basis in_context
