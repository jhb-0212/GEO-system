# 系统管理员使用说明（V1.0 首期）

> 适用对象：广州基地 GEO 系统（首期试点）的系统管理员（`users.is_system_admin = true`）与项目管理员。
> 编写依据：仓库 `aea6dda` 起的实现 + `docs/API契约.md` + `docs/冻结基线.md`。**本文只写已实现的东西**，未实现的端点单独标注"未实现"，不作为可用功能描述。

## 二、管理员身份与初始密码

- 首次部署时，`migrate` 一次性服务会执行 `alembic upgrade head && python scripts/seed.py`，种子里创建管理员：
  - 用户名：`SEED_ADMIN_USERNAME`，默认 `geo_admin`；
  - 密码：`SEED_ADMIN_PASSWORD`。**生产未设置该变量时 `seed.py` 直接拒绝启动**（日志会写"生产环境必须显式设置 SEED_ADMIN_PASSWORD"）；
  - 权限：`users.is_system_admin = true`，同时被加入 `gz-base` 项目并授予 `project_admin`。
- 开发环境未设 `SEED_ADMIN_PASSWORD` 时使用默认口令 `geo-admin-dev`，日志会明确标注"仅限本地"。
- **当前没有改密码接口**。需要改密码只能由 DBA 走评审后更新 `users.password_hash`，或重新执行 seed（seed 对已存在用户只补标志位，不会改密）。

## 三、登录与令牌（当前临时方案）

`auth/login` 未实现期间，本地/内网验证用调试令牌：

```powershell
cd C:\Users\EDY\Desktop\GEO系统开发\geo-system\backend
.\.venv\Scripts\python.exe scripts\dev_token.py --username geo_admin
# 可选 --minutes 指定有效期；默认取配置（480 分钟）
```

脚本行为：

- `APP_ENV` 不是 `dev` / `local` / `test` 时**直接拒绝**（`dev_token.py` 第 31 行守卫），所以生产环境拿不到调试令牌——这是预期行为，不是故障。
- 令牌为 JWT，调用时放在请求头：`Authorization: Bearer <token>`。

```bash
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/v1/projects
```

## 四、项目管理

### 4.1 查项目

`GET /api/v1/projects?page=1&page_size=20`

- 系统管理员看到全部项目；普通用户只看到自己已加入且 `is_active=true` 的项目。
- 返回：`{"data":[{"id","code","name","status"}], "meta":{"page","page_size","total"}}`，按 `code` 升序。

### 4.2 建项目

`POST /api/v1/projects`，需要系统级能力 `project.create`：

```json
{"code": "gz-demo", "name": "广州基地演示项目", "timezone": "Asia/Shanghai"}
```

- 成功：`201`，返回项目对象，并写一条 `audit_logs`（`action=project.create`）。
- `code` 重复：返回错误信封 `{"error":{"code":"project_code_exists","message":"项目 code 已存在"}}`。
- 新建项目**不会自动加入创建者**；创建后需要按 5.1 把自己或其他成员加入，否则你对这个项目没有项目级权限。

## 五、成员与角色授予

### 5.1 授予成员

`POST /api/v1/projects/{project_id}/members`，需要本项目 `project.member.manage`：

```json
{"user_id": "e47903f0-a3af-47b6-9a28-5c7b80f3b9dd", "role_code": "editor"}
```

- 允许授予的角色**只有 4 个**：`editor`、`reviewer`、`viewer`、`lead_ops`。
- `project_admin`、`sys_admin` **不可通过接口授予**：`project_admin` 目前仅由 seed / DBA 写库产生；`sys_admin` 只是能力映射字典，系统权限只认 `users.is_system_admin`。
- 越级授予返回 `403`，错误码 `permission_denied`，并写审计（`record_denial`）。
- 对已存在成员再次 POST 等价于改角色并重新激活。

### 5.2 改角色

`PATCH /api/v1/projects/{project_id}/members/{member_id}`

- 与授予同一套白名单校验。
- 项目管理员**不能调整同为 `project_admin` 的成员**（含降级），防止互夺权；系统管理员可以。
- 每次变更写 `record_permission_change`（before/after 角色码）。

### 5.3 查成员

`GET /api/v1/projects/{project_id}/members?page=1&page_size=20`，返回 `member_id / user_id / role_code / is_active`。

## 六、审计与导出

### 6.1 审计（当前只能查库）

审计写入 `audit_logs`，字段包括 `project_id`（系统级操作为 `NULL`）、`actor_id`、`action`、`target_type`、`target_id`、`payload`、`created_at`。

```bash
docker exec geo-postgres psql -U geo -d geo -c \
"select created_at, action, actor_id, target_id, payload from audit_logs order by created_at desc limit 20;"
```

常用 `action`：`project.create`、`permission_change`、`permission_denied`、`export`、`evidence.download`。

### 6.2 渠道导出

`GET /api/v1/channels/export`，需要 `export.data`：

- 返回 `text/csv`，列：`code,name,category,status,primary_domain`；
- 每次导出写一条 `audit_logs`，`action=export`，`payload` 含 `row_count`；
- 同步导出行数上限 5000（`export_sync_row_limit`），超限会报错并要求改异步导出；异步导出尚未实现；
- `lead_ops` 没有该能力，调用返回 403。

## 七、备份与恢复

### 7.1 备份

```powershell
cd C:\Users\EDY\Desktop\GEO系统开发\geo-system
.\deploy\scripts\backup_db.ps1 -AppEnv prod     # 生产：容器 geo-prod-postgres-1
.\deploy\scripts\backup_db.ps1                  # 开发：容器 geo-postgres
```

- 脚本按 `APP_ENV` 解析容器，也可显式 `-Container`；容器不存在或未运行会前置报错并列出当前容器。
- 产物为自定义格式 dump，落 `deploy/backups/`，命名 `geo-<时间戳>.dump`，导出后立即做 `pg_restore --list` 校验。
- 本地保留最近 7 份，更早的需运维同步到异地存储后清理。

### 7.2 恢复演练

```powershell
.\deploy\scripts\restore_drill.ps1
```

- 在**同一实例**建临时库还原并比对表数/关键计数，验证完删除临时库；
- 只证明备份可读与还原步骤正确，**不证明跨机器恢复能力**；跨主机恢复需在正式部署时单独演练（见第八节）。

### 7.3 RPO / RTO 现状

- 只有逻辑全量备份，无 WAL 归档，**PITR 未配置**；RPO 取决于备份频率，当前是手工执行；
- 恢复耗时未在真实数据量下测过。

## 八、上线前管理员必须知道的缺口

1. `auth/login` 未实现：生产只能由 DBA 生成令牌或等 B 补齐登录，**不能**用 `dev_token.py` 顶替。
2. 用户生命周期（创建/停用/改密）无接口，只能走 DBA。
3. 审计查询无接口，只能查库。
4. 证据文件已挂命名卷 `evidence_data`（容器重建不丢），但**未接对象存储**，多机部署前需定存储方案。
5. 监控只有健康检查端点，**缺 Worker 心跳、任务异常告警、日志集中管理**。
6. 证书、HSTS、防火墙、跨主机恢复、PITR 均未在真实主机验证。

## 九、常见故障排查

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| `401 unauthorized` | 没带 `Authorization` 或令牌过期 | 重新签发；生产等 `auth/login` |
| `403 project_forbidden` | 不是该项目成员，或成员已 `is_active=false` | 让系统管理员按 5.1 加入 |
| `403 permission_denied` | 角色缺对应能力码 | 查第六节能力矩阵，按 5.2 调整角色 |
| `409 project_code_exists` | 项目 code 重复 | 换 code |
| `503` 且 `/health/db` 失败 | 数据库不可用 | `docker compose ps` 看 postgres 是否 healthy；确认连的是 5433（开发）而不是本机 5432 |
| 服务都 Up 但接口 500 | `migrate` 未成功，库是空的 | `docker compose logs migrate`，确认 `alembic upgrade head` 与 seed 都完成 |
| 改了 api 容器后整站 502 | nginx 缓存了旧容器 IP | 已通过变量 upstream + Docker DNS 修复；若仍出现，`docker compose restart nginx` 后复查 |
