# 转化归因口径（C 侧）

> 目标：回答“哪条题目、哪个渠道、哪个 AI 引擎带来的线索”，而不是只记录一句 `lead_source`。
> 边界：C 只做字段、口径、巡检和统计底座；CRM 跟进界面、企微/电话系统由业务侧负责。

## 一、字段

`leads` 在原有 `lead_source`、`reported_ai_product`、`interested_course` 基础上新增：

| 字段 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `source_question_id` | UUID | 线索来自哪条题目 | FK `questions`，`SET NULL`；必须是当前项目题目 |
| `source_channel_id` | UUID | 线索来自哪个渠道 | FK `channels`，`SET NULL`；必须是当前项目渠道 |
| `source_engine_id` | UUID | 线索来自哪个 AI 引擎 | FK `ai_engines`，`SET NULL` |
| `landing_url` | String(512) | 承接页/落地页真实 URL | 可空；带 UTM 时保留完整 URL |
| `utm_campaign` | String(128) | 活动标识 | 推荐 `q{题目code}__{渠道code}` |

保留 `lead_source` 作为兼容字段：历史数据继续可读；新数据以三个外键为准。`reported_ai_product` 保留用户自报的 AI 产品文本，`source_engine_id` 是系统可统计的规范引擎。

## 二、写入规则

1. 前端/公开站提交线索时，`source_question_id`、`source_channel_id` 能传就传；不能传时留空，但巡检会记为 `lead_without_question` / `lead_without_channel`。
2. `source_question_id`、`source_channel_id` 必须属于当前项目；跨项目引用返回 `404 resource_missing`，防止串数。
3. `source_engine_id` 必须是已存在引擎；引擎停用不影响历史线索。
4. `utm_campaign` 建议格式：`q{qcode}__ch{channel_code}`，例如 `qQ07__chzhihu`；不要用中文空格或未编码的 `&`。
5. `landing_url` 必须是可访问的真实承接页，不填短链后台地址；短链只能放在 `note` 里做辅助。

## 三、漏斗口径

| 层级 | 口径 | 数据来源 |
| --- | --- | --- |
| 1. 引用覆盖 | 至少 1 条有效引用的 active 题目数 / active 题目数 | `monitoring_citations` ← `monitoring_samples` ← `monitoring_tasks` ← `question_versions` |
| 2. 品牌搜索/承接页访问 | 进入 `landing_url` 的会话数；没有埋点时只能做近似 | 公开站/埋点，暂不入库 |
| 3. 留资 | `leads` 总数、有效率 `is_valid` | `leads` |
| 4. 归因留资 | 带 `source_question_id` 且带 `source_channel_id` 的线索数 | `leads` |
| 5. 到访/成交 | `enrollment_status` 进入 `visited` / `enrolled` 等状态的数量 | `leads.enrollment_status` |

推荐看三个比值：

- **内容归因率** = 带题目归因的线索 / 全部线索；
- **渠道归因率** = 带渠道归因的线索 / 全部线索；
- **题目→留资率** = 某题归因线索数 / 该题有效引用数（引用为 0 时不计算，返回 `null`，不返回 0）。

## 四、统计维度

按题目、渠道、引擎分别聚合：

```text
leads_total
leads_valid
leads_attributed_question
leads_attributed_channel
leads_attributed_engine
leads_by_question[]
leads_by_channel[]
leads_by_engine[]
```

排序：按 `created_at` 降序取明细；聚合按留资数降序。分母为 0 时返回 `null`，不伪造 0。

## 五、已知边界

- 公开站是否真的记录 UTM、二维码、电话分机，取决于 A 侧承接页和业务侧配置；C 只保证字段能接。
- 企微/电话系统的“到访/成交”目前靠人工改 `enrollment_status`，没有自动回传。
- AI 答案不保证稳定显示电话或地址，因此不能用“答案里是否出现电话”作为唯一归因；以 `landing_url` + `utm_campaign` + 题目/渠道外键为准。
- 历史 `edge-validation` 线索没有归因字段，巡检会报 `lead_without_question` / `lead_without_channel`，这是预期，不回填猜测值。
